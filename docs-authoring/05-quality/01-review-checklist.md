# 01 · 单章审查清单

每写完一章，**作者自审一遍，再由另一个人（或另一次独立会话）复审一遍**。
自审能过但复审不过是常态——视角问题作者自己看不出来。

---

## A. 视角（最高优先级，一票否决）

- [ ] 通读全章，句子的主语是 **「你」** 或 **「助手」**，不是「开发者」「宿主」「系统」。
- [ ] 全章**没有任何代码块**（技能内容、提示词原文除外）。
- [ ] 没有出现 API 名、类名、函数名、包名、文件路径。
- [ ] 没有出现 `AC-x.x` 编号、权限名（`sidePanel`、`<all_urls>` 等）。
- [ ] 没有出现 A2UI / OpenUI / Vercel 等渲染器名（**仅第 23 章允许**，因为界面上就那么写）。
- [ ] 回答的是「我怎么用」，不是「它怎么实现」。

**快速自测**：随机挑 5 个句子，问「一个不写代码的人读了会更会用产品吗」。
有一句答不上来就要改。

---

## B. 结构

- [ ] 有开头一段，说明本章解决什么问题。
- [ ] **三个必备小节齐全**：「你能做什么」「网页版与扩展版的差别」「出问题了怎么办」。
- [ ] 只用了 `##` 和 `###`，没有 `####`。
- [ ] 篇幅在规定区间内（功能章 1000-1800 字，控制台单页 300-600 字，场景章 800-1200 字）。
- [ ] 章节自足：不依赖读者读过前一章才能看懂。

---

## C. 术语

- [ ] 界面元素名与 i18n 词典**逐字一致**（会话 / 打开 Console / 固定到页面 /
      运行步进 / 任务清单 / 运行细节 / 思考中… / 需要授权 …）。
- [ ] 六种交互卡的标题逐字正确。
- [ ] 形态称呼统一用 **网页版 / 扩展版 / Demo**，没用「插件版」「浏览器版」等变体。
- [ ] 没有出现禁用词（见 [../00-charter/03-terminology.md](../00-charter/03-terminology.md)）。
- [ ] 首次出现的概念给了一句话解释。

**核对方法**：把本章提到的界面文字列出来，逐条到 i18n 里搜。搜不到 = 措辞错了。

---

## D. 事实

- [ ] 每个功能描述都能追溯到来源（verify / i18n / 亲手验证过）。
- [ ] **亲手在 Demo 里跑过一遍**本章描述的操作。
- [ ] 数字（上限、时长、数量）来自源码而非记忆。
- [ ] 没有写 `docs/deferred-items.md` 里已推迟的功能。
- [ ] 不确定的地方用了规定的措辞（「通常」「多数情况下」），
      而不是含糊其辞或武断断言。

---

## E. 图与截图

- [ ] 本章分配的 Mermaid 图已画，节点名无代码符号。
- [ ] 图有图注和 `alt`，图注说明「该看出什么」。
- [ ] 截图数量达到本章要求。
- [ ] 每张截图紧跟在它所说明的步骤之后，不是堆在章末。
- [ ] 截图为深色主题，语言与文档版本一致。
- [ ] **截图无敏感信息**。
- [ ] 模型输出类截图有「示例运行结果，你的实际输出会有所不同。」
- [ ] 图里的关键信息，正文也用文字讲了（无障碍）。

---

## F. 两种形态

- [ ] 涉及形态差异的地方都说清楚了，没有把扩展版能力写成通用能力。
- [ ] 扩展版独有能力用了 `> **仅扩展版**：` 提示块。
- [ ] 每讲一处「扩展版更强」，同屏给出了对应的约束。
- [ ] 与 [../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) 的差异表不冲突。

---

## G. 链接与双语

- [ ] 所有内部链接指向真实存在的章节 slug。
- [ ] 交叉引用用了章节标题，不是「见上文」「如前所述」。
- [ ] 中英两版**结构完全一致**：小节数、图数、截图数一一对应。
- [ ] 英文版读起来是英文母语者写的，不是中文直译。
- [ ] 英文版的界面元素名用 i18n 的 `en` 值，不是自己翻译的。

---

## H. 复审专项

复审者除了走一遍上面的清单，额外做两件事：

**1. 照着文档操作一遍。**
按章节里的步骤在 Demo 里实操，看是否卡住、是否与描述不符。
这是发现"写的时候想当然"的唯一可靠方法。

**2. 找三处最可能出错的地方深挖。**
经验上是：数字（上限值）、措辞（界面原文）、形态归属（网页版还是扩展版）。

---

## I. 判定

任一 A 类未通过 → **打回重写**（视角问题不能局部修）。
C / D 类未通过 → 修正后重审。
其余 → 修正即可合入。
