# 04 · 视觉规范（移植自 VitePress 默认主题）

文档模块的排版、颜色、组件规格。**所有数值都取自 VitePress 默认主题源码**，
不是凭印象写的近似值，实现时照抄即可。

---

## 0. 先说清楚：为什么不直接用 VitePress

**结论：移植设计语言，不移植技术栈。**

VitePress 的排版确实是中文技术文档里少有的好范本，但它**不能直接搬进这个站点**：

| 冲突点   | 事实                                                                 |
| -------- | -------------------------------------------------------------------- |
| 框架     | VitePress 是 **Vue** 驱动的静态站生成器，站点是 **React**            |
| 构建形态 | 站点是多入口 Vite 应用（`index.html` / `demo.html` / `viewer.html`） |
| 已有能力 | chatbot 的帮助入口要深链到具体章节；站点已有一套 i18n 与导航         |

把站点换成 VitePress，或者把文档拆成一个独立的 VitePress 子站，
代价都是**打断 demo 与投放查看器**、**重做 i18n**、**帮助深链失效**。
不值得。

所以本规范的做法是：**把 VitePress 的设计决策抄进现有的 React 文档模块**——
它的价值本来就在排版尺度、颜色分层、容器语义这些**与框架无关**的部分。

**明确不引入的东西**（省得实现者纠结）：

- **亮色主题**。站点固定暗色，VitePress 每个色值只取 `.dark` 那一列。
- **首页 hero 版式**。站点已有自己的首页。
- Carbon Ads、赞助按钮等与本站无关的组件。
- Vue 的 `<script setup>` 组件本身——只抄 CSS 规格和结构，用 React 重写。

## 1. 颜色：三级色阶 + 一个半透明底

这是 VitePress 最值得抄的一条，**也是最容易抄错的一条**。

每个色相都有四档，**各有明确分工，不能混用**：

| 档位       | 用途                     | 约束                               |
| ---------- | ------------------------ | ---------------------------------- |
| `XXX-1`    | **带颜色的文字**         | 必须在 `XXX-soft` 底上满足对比度   |
| `XXX-2`    | 按钮等的 **hover 态**    | —                                  |
| `XXX-3`    | **实心背景**（如按钮底） | 必须能压住白字                     |
| `XXX-soft` | **容器/徽章的浅底**      | **必须是半透明 alpha，不能是实色** |

**`-soft` 为什么必须半透明**——这是设计意图，实现时不要"优化"成实色：
半透明才能**叠加**。提示容器里嵌一段行内代码时，
代码块的 soft 底叠在容器的 soft 底上，会自然加深一层，
形成正确的层次；换成实色就变成两块打架的色斑。

### 暗色取值（照抄，只取 `.dark`）

```
灰   gray-1  #515c67   gray-2  #414853   gray-3  #32363f   gray-soft   rgba(101,117,133,.16)
靛   indigo-1 #a8b1ff  indigo-2 #5c73e7  indigo-3 #3e63dd  indigo-soft rgba(100,108,255,.16)
绿   green-1 #3dd68c   green-2 #30a46c   green-3 #298459   green-soft  rgba(16,185,129,.16)
黄   yellow-1 #f9b44e  yellow-2 #da8b17  yellow-3 #a46a0a  yellow-soft rgba(234,179,8,.16)
橙   orange-1 #fb8c00  orange-2 #e46a02  orange-3 #b45309  orange-soft rgba(249,115,22,.16)
红   red-1   #f66f81   red-2   #f14158   red-3   #b62a3c   red-soft    rgba(244,63,94,.16)
紫   purple-1 #c8abfa  purple-2 #a879e6  purple-3 #8e5cd9  purple-soft rgba(159,122,234,.16)
```

### 功能色映射

| 功能      | 色相 | 用在哪                   |
| --------- | ---- | ------------------------ |
| default   | 灰   | 无语义的浅底、行内代码底 |
| brand     | 靛   | 链接、行内代码文字、强调 |
| tip       | 靛   | 提示容器                 |
| success   | 绿   | 成功、diff 新增行        |
| warning   | 黄   | 警告容器                 |
| danger    | 红   | 危险容器、diff 删除行    |
| important | 紫   | 重点容器                 |

### 接到站点已有 token 上

站点已有一套语义 token，**不要另起炉灶再来一套**，做映射：

| VitePress 角色   | 站点 token                 | 说明                        |
| ---------------- | -------------------------- | --------------------------- |
| `--vp-c-bg`      | `--color-bg` (#000000)     | 站点比 VitePress 更黑，可用 |
| `--vp-c-bg-alt`  | `--color-surface`          | 侧栏、代码块底              |
| `--vp-c-bg-soft` | `--color-surface`          | 表格隔行底                  |
| `--vp-c-text-1`  | `--color-text-main`        | 正文                        |
| `--vp-c-text-2`  | `--color-text-dim`         | 次要文字、表头、引用        |
| `--vp-c-border`  | `--color-border-color`     | 交互组件边框                |
| `--vp-c-brand-1` | `--color-accent` (#38bdf8) | **站点用青色，不是靛色**    |

> **brand 用站点自己的 `--color-accent`，不要引入 VitePress 的靛蓝**——
> 文档页和站点其余部分必须是同一个品牌色，否则一跳进文档就像换了个网站。
> 其余六个色相（绿/黄/橙/红/紫）站点没有，**按上表新增**，
> 它们只服务于容器和 diff，不会和站点风格冲突。

`--vp-c-text-3`（占位符级灰）站点没有对应值，新增 `#6a6a71`。
`--vp-c-divider` 用 `#2e2e32`；站点的 `--color-border-color` 是
`rgba(255,255,255,0.15)`，适合做**交互组件**边框，
但用作**分隔线**偏亮，两者要分开，不要合并成一个。

## 2. 排版

### 内容宽度——本节最重要的一个数

**正文列宽 `43rem`（688px）**，右侧有大纲时也是这个值。
这是 VitePress 排版舒适的主要原因：**一行大约 40 个汉字**，
再宽眼睛回行就会丢行。

其余宽度：

| 场景             | 值                    |
| ---------------- | --------------------- |
| 正文列（有大纲） | `43rem`               |
| 整站最大宽度     | `90rem` (1440px)      |
| 左侧栏           | `17rem` (272px)       |
| 右侧大纲列       | `16rem`，内容 `14rem` |
| 顶栏高度         | `4rem`                |

**断点**：`48rem` / `60rem` / `80rem` / `90rem`。
右侧大纲在 `80rem` 以上才显示，左侧栏在 `60rem` 以上常驻。

### 标题

| 元素 | 字号       | 其他                                                                         |
| ---- | ---------- | ---------------------------------------------------------------------------- |
| h1   | `2rem`     | 窄屏 `1.75rem`；`letter-spacing: -.02em`                                     |
| h2   | `1.5rem`   | **上方一条 `divider` 分隔线** + `padding-top: 1.5rem`，`margin: 3rem 0 1rem` |
| h3   | `1.25rem`  | `margin: 2rem 0 0`                                                           |
| h4   | `1.125rem` | `margin: 1.5rem 0 0`                                                         |

**h2 上面那条分隔线不要省。** 本手册每章都有很多平级小节，
没有这条线，读者滚动时分不清哪里是新一节的开始。
字重统一 `600`。

### 正文

- 段落 `line-height: 1.75`，`margin: 1rem 0`
- 列表项之间 `margin-top: .5rem`（`li + li`），列表 `padding-left: 1.25rem`
- 引用块：左侧 `2px` 竖线（`divider` 色）+ `padding-left: 1rem`，文字用 `text-2`
- 链接：`brand-1` + 下划线，`text-underline-offset: .125rem`，字重 `500`
- 表格：`th` 字号 `.875rem`、`text-2` 色、`bg-soft` 底；`td` 字号 `.875rem`；
  **偶数行加 `bg-soft` 底**；整体 `overflow-x: auto`（长表格横向滚动，不要压缩列宽）

### 中日韩断行——本手册必须加

```css
[lang]:where(:lang(zh), :lang(ja), :lang(ko)) {
  h1,
  h2,
  h3,
  h4,
  h5,
  h6,
  li,
  p {
    line-break: strict;
  }
}
```

**这条规则对中文版是硬要求**：不加的话，浏览器会把标点挤到行首，
出现「，」「。」开头的行。手册是中文优先，这个问题会出现在几乎每一页上。

### 锚点

标题 hover 时在左侧浮出 `#`（`margin-left: -.87em`，默认 `opacity: 0`）。
`scroll-margin-top` 要算上顶栏高度，否则点锚点跳过去标题会被顶栏盖住——
这是自建锚点最常见的 bug。

## 3. 自定义容器 ★ 对本手册价值最高

**这一节请优先实现。** 手册正文里有大量「★ 必写」「⚠ 不要写成…」
「绝不允许…」这类内容，现在只能靠**加粗**表达，
在长页面里几乎起不到警示作用。容器能让它们在视觉上跳出来。

规格：

- 字号 `.875rem`，容器内代码 `.8125rem`
- 内部段落 `line-height: 1.7142857`，`margin: .5rem 0`，首段 `margin: 0`
- **边框透明**，底色用对应的 `-soft`，文字一律 `text-1`
- 圆角 `.5rem`（与代码块一致）

| 容器          | 底色             | 手册里用在哪                                   |
| ------------- | ---------------- | ---------------------------------------------- |
| `tip`         | `tip-soft`       | 「换个说法也能做到」这类帮助读者的补充         |
| `info`/`note` | `default-soft`   | 中性说明、术语补充                             |
| `important`   | `important-soft` | 「这一条不能省」类的写作要求                   |
| `warning`     | `warning-soft`   | 「勾了不再询问等于把提交权交出去」类的代价告知 |
| `danger`      | `danger-soft`    | 隐私相关的硬事实，如「提炼出的结论会发给模型」 |
| `details`     | `default-soft`   | 折叠的长表格、取材配方                         |

**映射到手册的既有约定**（写作指导里已经在用这套记号，实现时按此转换）：

| 手册里的写法               | 渲染成              |
| -------------------------- | ------------------- |
| `> **⚠ …**`                | `warning`           |
| `**★ …必须…**`             | `important`         |
| 「绝不允许…」「必须逐字…」 | `danger`            |
| 「拍法见…」「配方见…」     | `details` 或 `info` |

容器里如果嵌代码块，代码块 `margin: .5rem 0`、圆角 `.5rem`、
代码背景**透明**（靠容器的 soft 底透出来）——这就是 §1 说的叠加效果。

## 4. 代码块

手册里有大量取材配方（`grep` / `sed` 命令），代码块的可用性直接影响写作效率。

基础规格：

- `line-height: 1.7`，`font-size: .875em`
- 底色 `bg-alt`，圆角 `.5rem`（`40rem` 以下**取消圆角并左右出血** `margin: 1rem -1.5rem`，
  让窄屏能用满宽度）
- `pre` 上下 `padding: 1.25rem`，`code` 左右 `padding: 1.5rem`
- 行内代码：`brand-1` 文字 + `default-soft` 底 + `padding: .1875rem .375rem` + 圆角 `.25rem`

**要实现的功能**（按对本手册的价值排序）：

1. **复制按钮**。右上角 `2.5rem` 方钮，默认透明、hover 显形，
   复制后变成「已复制」。手册的取材配方就是给人复制的，**这个必须有**。
2. **语言标签**。右上角小字（`.75rem`，`text-2`），hover 时让位给复制按钮。
3. **行高亮**。`highlighted` 类，底色 `default-soft`，左右出血保证整行贯通。
   用于在长配方里指出关键那一行。
4. **代码组 tabs**。同一件事的 zh/en 两种配方、或网页版/扩展版两种路径，
   用 tab 并排比写两个代码块清爽。激活态下方是 `brand-1` 的指示条。
5. `diff` 增删行（绿/红 soft 底 + `+`/`-` 符号）、`error`/`warning` 行。
   优先级最低，手册里少用。

## 5. 截图组件（VitePress 没有，必须自建）

手册要放 **192 张截图**，且每张都要有统一的说明。
VitePress 只把图片当普通 `<img>`，**这一块没得抄，要自己定**：

```
figure
├─ img         圆角 .5rem，1px divider 边框，最大宽度 100%
└─ figcaption  字号 .875rem，text-2 色，居中，margin-top .5rem
```

要求：

- **每张截图都必须有 caption**，写作规范里已经要求了统一的说明文案
  （如「示例运行结果，你的实际输出会有所不同。」）。
- 图片**加边框**。截图边缘常是深色，不加边框会和页面黑底糊在一起，
  读者看不出图从哪开始。
- 连续两帧的对照图（如「它填 / 它问」）**并排放置**，
  窄屏下改为上下堆叠，caption 合并为一条。
- 预留 `loading="lazy"`，192 张图不能一次性全加载。

## 6. 其余组件

| 组件          | 规格要点                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------- |
| 右侧大纲      | 固定定位，`14rem` 宽，底部 `2rem` 渐隐遮罩（`transparent → bg`）；只列 h2/h3             |
| 上一章/下一章 | 页脚左右两个块，从 `manifest.ts` 派生，**不要手写**                                      |
| 徽章 Badge    | 透明边框 + `-soft` 底 + `-1` 文字；用于「仅扩展版」这类标记                              |
| 侧栏          | `17rem`，底色 `bg-alt`                                                                   |
| z-index       | 页脚 10 / 局部导航 20 / 顶栏 30 / 顶部布局 40 / 遮罩 50 / 侧栏 60（`60rem` 以上降到 25） |
| 外链图标      | `://` 链接自动追加一个小箭头图标                                                         |

字体：

```
sans: -apple-system, BlinkMacSystemFont, sans-serif, 'Apple Color Emoji',
      'Segoe UI Emoji', 'Segoe UI Symbol', 'Noto Color Emoji'
mono: ui-monospace, 'Menlo', 'Monaco', 'Consolas', 'Liberation Mono',
      'Courier New', monospace
```

**不要引入 web font**。站点是静态托管，加载字体会拖慢首屏，
而系统字体栈在中文下的表现已经够好。

## 7. 落地顺序

按「对阅读体验的增益 / 实现成本」排：

1. **排版尺度 + CJK 断行 + 颜色映射**（§1、§2）——一次 CSS 变量改动，收益最大。
2. **自定义容器**（§3）——手册的警示内容全靠它。
3. **截图组件**（§5）——192 张图的呈现质量。
4. **代码块复制按钮 + 语言标签**（§4 的 1、2 条）。
5. 右侧大纲、上一章/下一章（§6）。
6. 代码组 tabs、行高亮、diff（§4 的 3-5 条）——按需。

**本地搜索不在本规范内**。VitePress 的本地搜索依赖 MiniSearch 与构建期索引，
在 React 侧要自己接。手册 33 章的体量下，
**先做侧栏 + 大纲 + 深链**已经够用，搜索作为后续项单独评估。

## 8. 验收

- [ ] 正文列宽是 `43rem`，不是撑满屏幕。
- [ ] h2 上方有分隔线。
- [ ] 中文段落没有行首标点（`line-break: strict` 生效）。
- [ ] 容器有五种以上语义，颜色与语义对得上（警告不是红的、危险不是黄的）。
- [ ] `-soft` 全是半透明；容器内嵌行内代码时有可见的层次叠加。
- [ ] 代码块有复制按钮，点了有反馈。
- [ ] 每张截图都有 caption 和边框。
- [ ] 品牌色是站点的 `--color-accent`，不是 VitePress 的靛蓝。
- [ ] 点击锚点后标题没有被顶栏遮住。
- [ ] `pnpm lint` 与 `pnpm build` 双绿。
