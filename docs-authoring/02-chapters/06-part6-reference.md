## 第 31 章 · 能力对照表：网页版 vs 扩展版 `comparison`

### 目标

读者用一张表就能定论：我这个形态能不能做某件事。

### 大纲

```
# 能力对照表
<一句话：怎么读这张表>
## 怎么判断我在用哪个       ← 与第 2 章一致，此处从简
## 对话能力
## 页面能力                 ← 差异最集中
## 产物与下载
## 管理与设置
## 权限与边界               ← 扩展版能力更强，边界也要更清楚
```

### 内容要点

按功能域分成 5 张小表，**不要用一张巨表**——手机上没法看。

每行三列：能力 / 网页版 / 扩展版，第四列放跳转链接。
取值统一用「支持 / 不支持 / 受限」三种，
「受限」必须在链接的章节里有详细说明。

数据来源：[../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) §2 的事实表。
**但不要照搬**——那张表里有 AC 编号和权限名，
本章面向用户，**AC 编号与权限名一律去掉**。

「权限与边界」一节要正面回答扩展版的安全顾虑，
用 [../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) §5 的约束表：

| 更强的能力     | 对应的约束                             |
| -------------- | -------------------------------------- |
| 能读任意网页   | 密码框的值不会被读取，也永远不会被记住 |
| 能操作任意网页 | 有副作用的操作要经你授权，可撤销       |
| 能跨标签页     | 只能用工作集内的，你自己开的它枚举不到 |
| 能切换标签页   | 不会抢走你的画面                       |
| 能下载         | 授权可查看可撤销                       |

### 图

- **M-31 能力边界示意**（flowchart）：
  用两个同心区域表示"网页版能触及的范围"⊂"扩展版能触及的范围"，
  并在扩展版的外圈标注约束（密码框、工作集边界等）。
  这张图要传达：**能力更大，但边界依然清晰**。

- 表格的每一行都能在正文某章找到出处，**结论完全一致**。

## 第 32 章 · 常见问题与排错 `faq`

### 目标

读者带着一个症状进来，能找到原因和解决办法。

### 大纲

```
# 常见问题与排错
## 怎么用这一章            ← 按症状找
## 助手没有响应
## 结果不对或跑偏
## 运行中途停了            ← 8 种原因，核心内容
## 传不了图 / 用不了语音
## 页面读不到 / 操作没生效
## 技能相关的问题
## 报问题时该提供什么      ← 诊断导出
```

### 内容要点

**必须按症状组织，不能按功能组织。**
读者不知道问题出在哪个模块，只知道现象。

**「运行中途停了」是本章核心**，把第 11 章的 8 种终止原因搬过来
（结论一致，措辞可精简），每条给出可执行的下一步。

其他必写症状与已知原因：

| 症状                           | 已知原因                                           | 出处                                    |
| ------------------------------ | -------------------------------------------------- | --------------------------------------- | --- | ------------------------------ | -------------------------------------- | -------- |
| 助手不能用技能了、变"笨"了     | 当前模型不支持工具                                 | 第 12 章                                |
| 完全没反应                     | 尚未配置大模型                                     | 第 12、22 章                            |
| 传不了图                       | 多模态关了 / 模型不接受图片                        | 第 10 章                                |
| 语音/摄像头用不了              | 浏览器拒绝权限；**扩展版需先在普通标签页授权一次** | 第 10 章                                |
| 页面操作没生效                 | 被策略拒绝 / 未授权                                | 第 14 章                                |
| 历史里的卡片点不动             | 只读快照                                           | 第 9 章                                 |
| 内容显示不全                   | 重复组只显示第一项                                 | 第 9 章                                 |
| 会话列表少了几条               | 部分会话文件无法读取，已跳过                       | 第 6 章                                 |
| 断网后恢复                     | —                                                  | `verify/human/07-network-resilience.md` |
| 上一轮卡住没做完               | 等待输入时中断，可点恢复                           | 第 5 章                                 |     | **刚看过的那一页忽然点不动了** | 那一页已不在工作集里，助手会重新读一次 | 第 15 章 |
| **它没处理完整个列表就收尾了** | 一轮最多同时开 32 页，撞上限了；把范围说小些分两轮 | 第 15 章                                |
| **我只想微调，它却整个重做了** | 固定模板的产物改不动，改用「现做的」重出一版       | 第 7 章                                 |
| **同样的需求，这次页数不一样** | 走了「现做的」，页数由内容决定                     | 第 7、27 章                             |

后四条是**新读者最容易误判为 bug 的行为**，必须都有归宿。
它们的共同点是「助手表现得不像我预期」，而实际上都是有确定原因的正常行为。
**「报问题时该提供什么」**：运行 ID（第 11 章）+ 诊断导出（第 23 章关于页）。
这一节能显著降低支持成本，不要省。

## 第 33 章 · 隐私与数据去向 `privacy`

### 目标

读者清楚知道：什么数据会离开我的设备、什么不会、我能控制什么。

> **本章是信任的最后一道关口，措辞必须极其准确。**
> 拿不准的一律不写，或写成"以你所在系统的实际配置为准"。
> **绝不允许为了好看而夸大隐私保护。**

### 大纲

```
# 隐私与数据去向
## 一张图看清数据去哪了
## 什么会被发给模型
## 什么永远不会被发送      ← 密码框
## 我上传的那份文件呢      ← ★ 读者上传公司文档前最想知道的
## 页面里的图片            ← 可关闭
## 助手记住了什么          ← 记忆与用户画像
## 你能控制什么            ← 集中给出所有开关
## 数据存在哪儿            ← 本机存储
## 网页版与扩展版的差别
```

### 内容要点

**「什么永远不会被发送」** —— 目前可确证的一条：
**密码框里的值不会进入感知结果，也永远不会被记住**
（依据扩展 e2e AC-14.8、AC-14.11）。
这一条要突出，但**不要扩大到"所有敏感信息都不会被发送"**——那是没有依据的。

#### ★「我上传的那份文件呢」

**此前遗漏。** 第 10 章和第 29 章都会讲到传文件，
读者在把公司文档拖进对话框之前，一定会想这个问题。**这里必须给出答案。**

按附件类型分开讲，**不要笼统说"文件是安全的"**：

| 你传的                     | 实际发出去的是什么                                   |
| -------------------------- | ---------------------------------------------------- |
| Word / Excel（docx、xlsx） | **在你的浏览器里抽成文字后，只发文字**；原文件不外发 |
| 文本类（txt、md、csv…）    | 文件里的文字（超过 32 KB 会截断）                    |
| pdf                        | **整份发给模型**                                     |
| 图片                       | 图片本身（可能被压缩后发）                           |

**第一行是好消息，第三、四行是需要读者知情的**。
按本章"绝不夸大"的原则，**四行都要写，不能只写第一行**。

依据：`packages/core/src/attachment/kind.ts`（分类与本地抽取）。
写之前**到界面上传一次实测**，不要只读代码就下结论。

#### ★「助手记住了什么」——这一节最容易写成假话

读者对画像的直觉是：**存在本机 = 不会外发**。
**这个直觉是错的，而本章绝不能顺着它写。**
画像之所以能帮你填表、能听懂「照老规矩来」，
正是因为**提炼出来的那几条结论会随每一轮对话一起交给模型**——
不发过去，它就无从知道你的习惯。

必须把两样东西**分开**讲，混在一起写就一定会误导：

| 东西                         | 去哪了                                                       |
| ---------------------------- | ------------------------------------------------------------ |
| 你答过的、选过的**原始记录** | **留在本机**，不外发                                         |
| 从中提炼出的**那几条结论**   | **每轮对话都会随提示一起发给模型**（有长度上限，超出的丢弃） |
| 这份画像本身                 | **只存在这台机器上**，不跨设备同步                           |

写法上有两条硬要求：

- **不许写成「你的偏好只存在本地、不会外发」**——第二行使它成为假话。
  正确的说法是：**原始记录不外发，提炼出的结论会作为背景交给模型。**
- **要顺势给出控制权**，紧接着指向第 23 章：
  嫌哪条不该发，就去把哪条删掉；不想要这整件事，就把学习关掉。
  **先说实话、再给开关**，顺序不能反——先安抚再补充细节，读者会觉得被糊弄。

依据：`packages/runtime/src/profile/inject.ts`（画像如何进入提示、上限与截断）、
`.work/feature-inventory.md` D29（跨设备同步属于延后事项，因此"只在这台机器"是当前事实）。
**写作时必须复核 D29 是否仍未实现**，一旦实现，第三行立刻变成假话。

**「你能控制什么」集中列出所有开关及其位置**，这是本章最实用的一节：

| 我想控制                     | 开关在哪                                           |
| ---------------------------- | -------------------------------------------------- |
| 页面里的图片要不要外发       | 第 13 章 / 设置 → 多模态                           |
| 助手要不要从我的回答里学习   | 第 23 章 → 隐私与用户画像                          |
| **它记住的某一条不对**       | **第 23 章 → 隐私与用户画像 → 逐条删掉那一条**     |
| 技能脚本能不能联网           | 第 23 章 → 沙箱与安全                              |
| 已经记住的授权               | 第 23 章 → 信任相关设置                            |
| 助手记住的内容               | 第 20 章 → 会话与记忆                              |
| **要不要让它把对话存成技能** | **第 23 章 → 智能体运行时 → 技能自动生成**         |
| **哪些页面操作不用再问我**   | **第 14 章确认卡上的「不再询问」，撤销在第 23 章** |

**每个开关都要给出确切位置，并在写作时到界面上核对一遍。**
