## 第 1 章 · 认识 WebSkill 助手 `intro`

### 目标

读者读完能说出「这个助手能替我做三件我以前要手动做的事」，并知道下一步该读哪章。

### 大纲

```
# 认识 WebSkill 助手
<开场：2 句，用一个具体场景切入，不要讲技术>
## 它能替你做什么          ← 三个真实例子，每个配一张结果截图
## 它和普通聊天机器人有什么不同   ← 三点：会用技能、会读页面、会给你看过程
## 它不会做什么            ← 诚实说边界，建立信任
## 从哪儿开始
```

### 内容要点

**「它能替你做什么」用三个 Demo 里真实跑得出来的例子**，每个例子一句话需求 +
一张结果截图：

| 例子               | Demo 素材                                       | 展示什么           |
| ------------------ | ----------------------------------------------- | ------------------ |
| 出一份运营报告     | 快捷提示「生成当前项目的敏捷运营报告…」         | 技能产出结构化报告 |
| 总结我正在看的页面 | 快捷提示「读取我当前正在看的这个页面…」         | 页面感知           |
| 做一块交付监控大屏 | 快捷提示「在新窗口打开当前项目的交付监控大屏…」 | 产物投放           |

**「它和普通聊天机器人有什么不同」** 是本章的核心差异化，三点：

1. **会干活，不只会说话**——它能调用技能和工具，产出文件、页面、报告。
2. **知道你在看什么**——它能读你当前的页面，不用你复制粘贴。
3. **过程透明**——每一步调用了什么、结果是什么，你都看得见。

**「它不会做什么」** 必须写，且要具体：

- 不会在没有你同意的情况下做有副作用的操作
- 不会读取密码框里的内容
- 结果由模型生成，可能出错，重要结论要自己核对

### 取材

| 优先级 | 材料                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------ |
| P0     | `packages/chatbot/src/i18n.ts` 的 `welcome.*`（10 条）——欢迎页三张能力卡就是官方对产品的自我介绍 |
| P0     | 站点仓库 `src/demo/webskill/quickPrompts.ts`                                                     |
| P1     | `docs/overall-requirements.md`（取价值主张，**必须改写成用户语言**）                             |

`welcome.capability.*` 三条（技能按需调用 / 生成式 UI / 运行透明度）
就是产品自己总结的三大特点，本章的「有什么不同」应与之呼应。

- 全章无任何技术名词（MCP、SDK、工具调用等一律不出现）。

## 第 2 章 · 网页版与扩展版 `editions`

### 目标

读者能判断自己在用哪个形态，并知道该期待什么能力、不该期待什么。

### 大纲

```
# 网页版与扩展版
<开场：一句话说清两者的本质区别>
## 怎么判断我在用哪个      ← 肉眼可辨的特征
## 网页版：住在网站里的助手
## 扩展版：住在浏览器里的助手
## 能力差在哪              ← 精简对照表，详表指向第 31 章
## 我该用哪个
```

### 内容要点

**本质区别**（这句话全书统一）：

> 网页版嵌在某个网站里，视野和手脚都局限在那一个网站；
> 扩展版装在浏览器上，能看到和操作你打开的任意网页，还能跨多个标签页干活。

**「怎么判断我在用哪个」** 给肉眼特征：

| 特征                | 网页版                                  | 扩展版       |
| ------------------- | --------------------------------------- | ------------ |
| 入口位置            | 网站页面内（Demo 里是右下角的助手抽屉） | 浏览器侧栏   |
| 关掉网站后          | 助手也没了                              | 助手还在     |
| 打开 console 的路径 | 网站内的技能中心                        | 扩展的选项页 |

**「能力差在哪」在本章只放精简版**（5-6 行），完整矩阵在第 31 章，
避免入门章被大表压垮。

### 取材

| 优先级 | 材料                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| P0     | [../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) §2 事实表 |
| P0     | `examples/browser-extension/manifest.json`                                               |
| P1     | `e2e-extension/*.spec.ts` 用例名                                                         |

- **M-02 两种形态对比**（flowchart，双 subgraph）：
  骨架已在 [../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) §1 给出，直接采用。

### 截图

| 编号          | 内容                                        | 要点                             |
| ------------- | ------------------------------------------- | -------------------------------- |
| S-editions-01 | Demo 里的网页版助手（抽屉展开，含所在网站） | 必须带上网站界面，体现"嵌在里面" |
| S-editions-02 | 扩展版侧栏助手（旁边是任意一个网页）        | 体现"独立于网页存在"             |

### 判据

- 「怎么判断」的特征真实可辨，不依赖用户查看设置。
- 精简对照表的每一行在第 31 章都有对应详解且**结论一致**。
- 不出现权限名（`<all_urls>`、`tabs` 等），只说能力。

## 第 3 章 · 五分钟上手 `quickstart`

### 目标

读者跟着做完，能在 Demo 里完成一次带技能调用的完整对话，并看懂结果。

### 大纲

```
# 五分钟上手
<开场：说明接下来会做什么、大概多久>
## 第一步：打开 Demo
## 第二步：打开助手
## 第三步：提出第一个需求      ← 用快捷提示，降低门槛
## 第四步：看助手干活
## 第五步：拿到结果
## 你刚才用到了什么            ← 回指后续章节，形成阅读地图
## 接下来读什么
```

### 内容要点

- **必须用快捷提示起步**，不要让读者自己想提示词——第一次就失败会劝退。
  推荐用「分析当前迭代的燃尽情况，判断能否按时收尾，说明依据和风险」，
  它执行快、结果直观、能体现技能与数据读取。
- **第四步是本章的价值所在**：教读者看运行中的界面（思考中、工具调用、运行步进），
  但只讲「你会看到这些，它们表示助手在干什么」，
  详细解读留给第 11 章并给链接。
- **「你刚才用到了什么」** 用表格把刚才的每一步映射到章节，
  这是全书的导流枢纽。

### 取材

| 优先级 | 材料                                               |
| ------ | -------------------------------------------------- |
| P0     | 站点 `src/demo/webskill/quickPrompts.ts`           |
| P0     | `verify/agent/00-overview.md`、`01-environment.md` |
| P0     | 自己在 Demo 里完整跑一遍并录屏（截图从录屏里截）   |

- 明确标注「示例运行结果，你的实际输出会有所不同」。
