**第 3 轮写**，此时文风已定型，可以批量推进。

## 0. 本部分的通用规则

### 0.1 小节顺序必须对齐界面

第 19-23 章的小节顺序**严格照抄** `packages/console/src/react/nav.ts`
的 `CONSOLE_NAV`。界面上是什么顺序，文档就是什么顺序，读者才好对照。

### 0.2 每页用统一小节模板

模板见 [../01-architecture/03-page-templates.md](../01-architecture/03-page-templates.md) §3：
做什么用 → 你在这里可以 → 截图 → 常见用法。

### 0.3 purpose 必须改写，不能照抄

界面上每页都有一句 `purpose`，是很好的起点，
但**其中不少仍是技术表述**，直接搬进用户文档就是视角事故。对照示例：

| 页面         | 界面原文（purpose）                             | 文档该怎么写                                           |
| ------------ | ----------------------------------------------- | ------------------------------------------------------ |
| 审计日志     | 发布、回滚与状态变更的哈希链记录。              | 谁在什么时候改了什么，这里有一份改不掉的流水账。       |
| 沙箱与安全   | 执行器档位、网络策略与逐能力审批。              | 技能脚本能用多大权限、能不能联网、哪些能力要一事一议。 |
| 会话与记忆   | 会话消息、三个记忆作用域，以及中断运行的快照。  | 助手记住了什么、在哪一层记的，以及没跑完的运行停在哪。 |
| 完整性与清单 | 按 manifest 与 lockfile 做逐文件 SHA-256 校验。 | 检查已安装的技能文件有没有被改动过。                   |
| 智能体运行时 | 循环护栏、交互策略、路由策略与输出形态。        | 助手最多干多久、卡住了怎么办、结果以什么形式给你。     |

**规则**：`purpose` 里出现 SHA-256、manifest、lockfile、哈希链、作用域、
档位、护栏这类词时，一律改写。

### 0.4 页面名保留中英对照

小节标题写成 `### 技能库（Library）`，因为用户的界面可能是英文。

### 0.5 取材公共项

以下材料在第 18-23 章通用，各章不再重复列出：

| 材料                                           | 用途                                   |
| ---------------------------------------------- | -------------------------------------- |
| `packages/console/src/react/nav.ts`            | 分组与页面顺序的唯一真相               |
| console i18n 的 `page.<id>.label` / `.purpose` | 页名与用途（**不要用 `.capability`**） |
| `packages/console/src/react/pages/**`          | 确认页面上实际有哪些控件               |
| `verify/agent/17` ~ `24`、`26`                 | 各组的验收清单                         |

## 第 18 章 · 控制台导览 `console-tour`

### 目标

读者会打开控制台、看懂导航结构、能快速找到任何一个页面。

### 大纲

```
# 控制台导览
## 什么时候需要控制台      ← 先说价值，别一上来讲界面
## 怎么打开                ← 两种形态入口不同
## 六个分组分别管什么      ← 全书查找地图
## 概览页：一眼看健康度
## 快速跳转                ← 命令面板
## 网页版与扩展版的差别
## 出问题了怎么办
```

### 内容要点

**「什么时候需要控制台」**：日常对话不需要进控制台，
以下情况才需要——装新技能、查为什么失败、改模型、调整权限、看用量。
这样读者才知道该不该读第四部分。

**「六个分组分别管什么」是全书的查找地图**，用一张表：

| 分组 | 管什么                                           | 页数 |

| 概览 | 工作区健康度、待办、最近运行                     | 1    |
| 技能 | 装了什么技能、改技能、导入导出、校验             | 4    |
| 运行 | 每次运行的记录与详情、会话与记忆                 | 3    |
| 治理 | 审批、审计、版本、评估、洞察                     | 5    |
| 连接 | 模型、MCP 端点、页面提供的工具                   | 4    |
| 设置 | 运行时、沙箱、界面、提示、信任、隐私、外观、关于 | 8    |

**入口差异**（形态差异在本章很关键）：

|      | 网页版                                                                        | 扩展版                                       |
| ---- | ----------------------------------------------------------------------------- | -------------------------------------------- |
| 入口 | 网站内的技能中心（Demo 里是左侧导航的技能中心），或对话头部的「打开 Console」 | 扩展的选项页                                 |

## 第 19 章 · 技能管理 `console-skills`

覆盖 4 页，顺序固定：技能库 → 编辑器 → 安装与导出 → 完整性与清单。

### 各页要点

**技能库（Library）** — 所有已安装技能的来源、状态与使用情况。

- 用 Demo 的 13 个内置技能做实例，正好一屏能展示。
- 讲清「来源」的意义：内置的 / 你装的 / 页面临时提供的，来源不同信任度不同。

**编辑器（Editor）** — 编辑技能文件，保存即校验。

- 这是全书**唯一允许出现代码块**的地方（展示技能文件内容）。
- 要强调：保存时会自动校验，写错了会当场告诉你。
- 与第 30 章（让助手改技能）联动，给链接。

**安装与导出（Install & Export）** — 从压缩包、URL 或目录安装，也能打包分发。

- 三种安装方式各给一段步骤。
- **安装是引入外部代码的行为**，必须在这里提示风险，并链接到信任设置。

**完整性与清单（Integrity & Manifest）** — 检查技能文件有没有被改动过。

- 用户语言改写要点：这页是给你确认「我装的技能还是原来那个吗」。
- 什么时候该来这里看：怀疑技能行为异常、从不明来源装过技能之后。

## 第 21 章 · 治理与复核 `console-governance`

覆盖 5 页：审批队列 → 审计日志 → 版本 → 评估 → 洞察。

> 这是最容易写成开发者视角的一章。**始终站在"我作为使用者，
> 为什么要关心这个"** 的角度写。

### 各页要点

**审批队列（Review Queue）** — 候选技能进技能库前的人工审查。

- 用户视角的价值：**新技能不会不打招呼就装进来**，你可以先看再决定。
- 与第 30 章（让助手改技能）强关联：助手生成的技能会先到这里。

**审计日志（Audit Log）** — 谁在什么时候改了什么，一份改不掉的流水账。

- 不要提哈希链。用户要知道的是：**记录不可篡改**，出了问题能追溯。

**版本（Versions）** — 版本历史与回滚。

- 用户视角：技能改坏了可以退回上一版。给出回滚的操作步骤。

**评估（Evaluation）** — 批量跑一组任务，看结果稳不稳。

- 用户视角：改完技能后，用它验证有没有改坏。

**洞察（Insights）** — 评分、重复技能、依赖关系、使用统计。

- 用户视角：哪些技能常用、哪些重复了可以清理。

## 第 22 章 · 连接 `console-connections`

覆盖 4 页：大模型 → MCP 端点 → WebMCP 工具 → 页面技能。

### 各页要点

**大模型（LLM）** — 助手可以用的模型列表。

- 界面 purpose 已经写得很好，可较多保留：
  可按会话选择，未选择时用默认项，**一个都没配时回退到内置演示模型**。
- 与第 12 章呼应，第 12 章讲"怎么选"，这里讲"怎么配"。

**MCP 端点（MCP Endpoints）** — 外部工具服务的连接状态与它提供的工具。

- 用户语言：这里接的是**你所在系统之外**能提供工具的服务。
- 要讲清可以**逐个工具启停**——这是用户能实际操作的部分。

**WebMCP 工具（WebMCP Tools）** — 当前页面通过浏览器通道给模型的工具。

**页面技能（Page Skills）** — 当前页面声明的临时技能，随页面生成或销毁。

## 第 23 章 · 设置 `console-settings`

覆盖 8 页，是本部分页数最多的一章。
顺序：智能体运行时 → 沙箱与安全 → 生成式 UI → 快捷指令 → 信任与签名 →
隐私与用户画像 → 外观 → 关于与诊断。

### 各页要点

**智能体运行时（Agent Runtime）** — 助手最多干多久、卡住了怎么办、结果什么形式。

- **与第 11 章的 8 种终止原因直接呼应**：这里就是调"轮次上限""时长上限"的地方。
- 必须给出默认值（从 `packages/runtime/src/engine/limits.ts` 取实数）。

**沙箱与安全（Sandbox & Security）** — 技能脚本的权限、能否联网、哪些能力要一事一议。

- 用户语言改写"执行器档位"：脚本能用多大权限。
- 与第 7 章"技能跑在哪里"呼应，这里是详细版。

**生成式 UI（Generative UI）** — 由哪套框架渲染、外观如何。

- **本页是全书唯一可以出现渲染档名称的地方**（因为界面上就这么写）。
- 与第 9 章呼应：第 9 章的"重复组只显示第一项"就是渲染档差异导致的，
  在这里说明换档可能改变呈现。

**快捷指令（Quick Prompts）** — 欢迎页上一点即发的常用指令。

- 教读者**自己加一条**——这是设置里最有获得感的操作。
- 用 Demo 的现成快捷提示做例子。

**信任与签名（Trust & Signing）** — 信任哪些来源、没签名的技能怎么办。

- 与第 19 章（安装）呼应。
- **页面操作的"已记住授权"也在信任相关位置管理**，第 14 章的撤销路径指向这里，
  写作时**先在界面上确认撤销入口的确切位置**，别写错路径。

**隐私与用户画像（Privacy & User Modeling）** — 助手是否从你的回答里学习、本机留了什么。

- 第 33 章的主要素材来源。
- 要写清：怎么关掉学习、怎么清除已保留的内容。
- **★ 这一页要按「看得见 → 改得动 → 带得走」三段写**，它是全书对"我能控制它"
  这个承诺兑现得最实的地方，只写一句"可以关掉"是浪费：
  - **看得见**：它记住的东西**不是一团黑盒**，是一条条能读懂的大白话结论，
    每条还带一个**把握程度**的标记。写作时要点出「你能逐条读」这件事本身
    ——大多数人预期的是一个看不懂的开关。
  - **改得动**：**每一条都能单独删掉**，不是只能一键清空。
    要给出「哪条不对删哪条」的操作示范，删除有二次确认。
    这一条和第 8 章的建议值、第 28 章的表单建议是同一件事的两端：
    **那边它凭这些条目给建议，这边你能把不认可的条目拿掉**，
    两处必须互相链接，否则读者不知道建议是可以纠正的。
  - **带得走**：可以**导出**成一份文件、也能**导入**。导出时**可以先排除掉几条不想带走的**；
    导入前会给一份**变化预览**（哪些是新增、哪些会被覆盖），并显示这份画像**来自哪个站点**。
    不写预览这一段，读者不敢点导入。
- **必须写「导出文件里混进密码怎么办」**：
  如果一份画像里含有像凭据的内容，**导出和导入都会被直接拒绝**，不是警告后放行。
  理由要讲给读者听：**这种文件常被顺手发邮件、丢进网盘**，
  一旦裹带凭据就是长期泄漏。这是本页最能建立信任的一条，别漏。
- **默认状态要写准**：SDK 出厂**默认关闭**（`13-privacy-profile.md` A-94），
  而 Demo 为了演示**默认打开**。**以出厂默认为准来写正文**，
  Demo 的设定放在截图说明里注明，不要写反。
- **画像为空时点「提炼」不会凭空造条目**（A-95），会给一句明确的空结果说明。
  这一条值得写，因为它正面回应「它会不会自己脑补我」。
