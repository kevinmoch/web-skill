### 批次 P · 读本机下载的文件（6 张，**仅扩展版**）

拍摄前必须先做两件事，否则一张都拍不出来：
**① 打开这个能力**（出厂默认关闭）；
**② 在 `chrome://extensions` 里打开「允许访问文件网址」**。

| 编号           | 内容                                         | 章  |
| -------------- | -------------------------------------------- | --- |
| S-downloads-01 | 列清单的确认卡                               | 17  |
| S-downloads-02 | 读取某个文件的确认卡（文件名 + 大小可读）    | 17  |
| S-downloads-03 | 「不再询问」勾选项特写                       | 17  |
| S-downloads-04 | 清单里某项被标成读不了                       | 17  |
| S-downloads-05 | `chrome://extensions` 开「允许访问文件网址」 | 17  |
| S-downloads-06 | console 里撤销这条授权                       | 17  |

**S-downloads-05 要在开关打开之前拍**——开完就回不去了，
除非再手工关掉，而关掉会导致前面拍好的图作废。**把它排在这一批的第一张。**

**下载目录要先清干净。** 列清单那张图会把你真实的下载记录拍进公开文档。
建议新建一个干净的浏览器配置，只下载几个无害的示例文件再拍。
S-downloads-04 需要一个**读不了的格式**（比如 `.zip`）躺在目录里才能拍到。

### 批次 O · 「它记得你」（7 张，**必须按时间顺序拍**）

这一批和别的批次不同：**它不能在清场后一次拍完**，
因为要拍的正是「用久了之后它才有的东西」。顺序拍错就得推倒重来。

| 编号              | 内容                                     | 章  |
| ----------------- | ---------------------------------------- | --- |
| S-interactions-10 | 画像为空时的卡片（没有任何建议）         | 8   |
| S-privacy-02      | 画像条目列表（每条带把握程度标记）       | 23  |
| S-privacy-03      | 删除单条时的确认                         | 23  |
| S-privacy-04      | 导入前的变化预览（新增/覆盖 + 来源站点） | 23  |
| S-privacy-05      | 含凭据的画像被拒绝的提示                 | 23  |
| S-interactions-09 | 有建议值和建议依据的卡片                 | 8   |
| S-case-form-07    | 表单里带建议值的字段特写（依据可读）     | 28  |

**拍摄顺序就是上表顺序，理由如下**：

1. **先拍空的**（S-interactions-10）。清场后第一次进入，画像必然是空的，
   这张图过了这个窗口就得手工清空重来，而手工清空容易残留。
2. **再正常用一段时间**把画像攒出来——按第 29 章那类场景真实操作，
   多答几次问题、多做几次选择。**不要手工往里塞条目**：
   塞进去的条目和真实提炼出来的措辞不一样，读者一对比就露馅。
3. **攒够之后**再拍 S-privacy-02，以及带建议的 09 / S-case-form-07。
4. **删除和导入的两张放在最后**（03、04、05），因为它们会改动画像内容；
   放在前面拍会让后面几张图里的条目对不上。

S-privacy-05 需要一份**故意含凭据的画像文件**来触发拒绝。
自己造一份用于拍摄即可，**但不要把真实凭据写进去**——
截图会进公开文档。用明显是假的占位内容，且拍完即删。

S-interactions-09 与 S-interactions-10 是**对照图**，
必须是同一种卡片、同一个字段，否则对照不成立。

上面的批次划分是**跨章的拍摄分组**，各批次标注的张数为估算，
用于安排工作量；以各章指导里的编号清单为准。
