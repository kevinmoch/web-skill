# 01 · Mermaid 图谱

33 张图的完整清单。每张给：所属章、类型、要传达什么、必含要素。
部分关键图直接给出骨架代码。

---

## 1. 画图的三条原则

**原则一：图里的每个节点，用户要么能在界面上看到，要么能感知到它发生了。**
出现 `ChatEngine`、`ToolSource`、`agentLoop` 这类名字即为废图。

**原则二：能用一句话说清的不要画图。**
30 张是上限不是指标。第 25 章就是刻意不画图、复用已有图的例子。

**原则三：图不能替代文字。**
每张图前后都要有文字说明它在讲什么、读者该看出什么。
图只是把文字里的关系可视化，不承载独有信息（无障碍要求）。

## 2. 暗色渲染配置

站点是纯暗色（`--color-bg: #000000`），**Mermaid 默认主题是亮色，直接用会出白块**。

每个 `.mmd` 文件开头统一加：

```
%%{init: {
  'theme': 'base',
  'themeVariables': {
    'background': 'transparent',
    'primaryColor': '#161616',
    'primaryTextColor': '#FAFAFA',
    'primaryBorderColor': 'rgba(255,255,255,0.15)',
    'lineColor': '#A1A1AA',
    'secondaryColor': '#222222',
    'tertiaryColor': '#161616',
    'fontSize': '14px'
  }
}}%%
```

强调色（用于高亮关键节点）用站点的 `--color-accent`：`#38bdf8`。

**渲染后必须在站点里肉眼确认无白底**——这是唯一一个主题，出问题非常显眼。

源文件保存在 `docs-authoring/.work/diagrams/M-NN.mmd`，
产物 SVG 放 `public/docs-assets/<slug>/M-NN.svg`。**源文件必须保留**，否则后续改不动。

## 3. 图清单

### 第一部分

**M-01 全书能力总览**（第 1 章 + 文档首页）· `flowchart LR`
以「你的一句话」为起点，分出四条支线：正常对话 / 调用技能 / 读写页面 / 产出文件，
每条支线末端标注对应章节。首页用它做导航图。

**M-02 两种形态对比**（第 2 章）· `flowchart TB` + 双 `subgraph`
骨架已在 [../04-sourcing/03-web-vs-extension.md](../04-sourcing/03-web-vs-extension.md) §1 给出，直接采用。

**M-03 一次对话的完整流程（简化版）**（第 3 章）· `flowchart LR`
`你提问 → 助手理解 → 选技能或工具 →（必要时问你）→ 执行 → 给结果`。
**必须与 M-11 的结论一致**，M-11 是它的详细版。

### 第二部分

**M-04 界面分区**（第 4 章）· `flowchart TB` + 嵌套 `subgraph`
上（头部）/ 中（消息区）/ 下（输入区），侧边（会话列表）。
配合全景截图使用，图给结构，截图给实貌。

**M-05 一条消息的生命周期**（第 5 章）· `stateDiagram-v2`

```
stateDiagram-v2
    [*] --> 编辑中
    编辑中 --> 生成中: 发送
    生成中 --> 已完成: 正常结束
    生成中 --> 已停止: 你点了停止
    生成中 --> 失败: 出错
    已停止 --> 生成中: 重试
    失败 --> 生成中: 重试
    已完成 --> [*]
```

要点：`已停止` 节点旁必须注明**已生成的内容会保留**。

**M-06 会话与上下文**（第 6 章）· `flowchart LR` + 双 `subgraph`
两个会话并列，各自内部消息相连、跨会话无连线，
直观解释「换会话就是重新开始」。

**M-07 从一句话到技能产出**（第 7 章）· `flowchart LR`
`你的需求 → 判断该用哪个技能 → 激活技能 → 在沙箱里执行 → 产物回到对话`。
节点名用运行步进里的真实阶段名（路由 / 激活 / 执行 / 完成）。

**M-08 六种卡片的辨认树**（第 8 章）· `flowchart TD`
根「助手需要什么」→ 六个分支（一句回答 / 是否确认 / 多个字段 / 从几项里选 /
一次许可 / 一个文件）→ 叶子是六种卡片标题。卡片标题必须逐字用界面原文。

**M-09 一个回答可以长成什么样**（第 9 章）· `flowchart LR`
从「助手的回答」分出：文字 / 表格 / 图表 / 表单 / 看板 / 文档，
每个标注「可交互」或「只读」。

**M-10 一张图片进入对话的路径**（第 10 章）· `flowchart TD`
三个来源（选文件 / 拍照 / 粘贴）→ 成为输入框里的附件 → 你点发送 →
两道检查（多模态是否开启 / 模型是否接受图片）→ 发出 或 被拒并提示。
这张图同时解释了「为什么我传不了图」。

**M-11 一次运行的阶段流转**（第 11 章）· `stateDiagram-v2` · **全书最重要的原理图**

```
stateDiagram-v2
    [*] --> 路由中
    路由中 --> 激活技能
    路由中 --> 执行工具
    激活技能 --> 执行工具
    执行工具 --> 等待输入: 需要你回答
    等待输入 --> 执行工具: 你提交了
    执行工具 --> 路由中: 还需要下一步
    执行工具 --> 已完成
    路由中 --> 失败
    执行工具 --> 失败
    等待输入 --> 失败: 超时未提交
    已完成 --> [*]
    失败 --> [*]
```

阶段名**必须**用 `status.*` / `trace.phase.*` 的界面原文。
`失败` 旁边注明「原因见第 11 章的 8 种情况」。

**M-12 运行界面的信息层次**（第 11 章）· `flowchart TD`
`运行状态（当前阶段）→ 运行步进（每一步）→ 单步详情（工具名 / 参数 / 结果 / 耗时）`。
告诉读者细节该展开哪里看。

**M-13 模型能力决定你能做什么**（第 12 章）· `flowchart TD`
从「当前模型」出两个判断菱形（支持工具？支持图片？），
导向能做/不能做的能力集合。**必须体现"不支持工具 = 不能用技能和页面能力"**。

### 第三部分

**M-14 助手能看到页面的哪些部分**（第 13 章，第 25、33 章复用）· `flowchart TB`
一个页面的示意，三类标注：
**会读**（正文、表格、表单标签）、**不会读**（密码框）、**可开关**（图片）。
本图在第 33 章隐私章复用，是全书隐私叙事的主力图。

**M-15 一次页面操作的授权流程**（第 14 章）· `flowchart TD`

```
flowchart TD
    A["助手提出要做的操作"] --> B{"你的决定"}
    B -->|允许| C["执行这一次"]
    B -->|允许并记住| D["执行，且以后同类操作不再问"]
    B -->|拒绝| E["不执行，助手说明它没做"]
    D -.->|"随时可在设置里撤销"| F["撤销后恢复每次询问"]
```

必须体现**用户始终有否决权**，且「记住」有回头路。

**M-16 工作集**（第 15 章）· `flowchart LR` + 双 `subgraph`
「工作集内的标签页（助手可用）」与「你自己开的其他标签页（助手看不到）」，
中间画出明确的隔离边界。直接回应安全顾虑。

**M-17 产物的四种去向**（第 16 章）· `flowchart LR`
`产物 → 在对话里看 / 新窗口放映（需你同意）/ 下载到本地 / 打印成 PDF`。
「需你同意」必须标在边上。

**M-18 一次读取要过几道门**（第 17 章）· `flowchart LR` · **仅扩展版**
`你说「看看我刚下载的那份」→【卡 1】允许列清单？→ 列出（不含路径）→
你指定一份 →【卡 2】允许读「文件名 · 大小」？→ 读出文字 → 交给模型`。

两个【卡】节点必须**视觉突出**（与 M-28 的「【停】」用同一种强调样式，保持全书一致）。
另挂两条分支：`不允许 → 到此为止`、`格式不支持 → 在列清单时就已标出`。

> **这张图与 M-17 必须画得明显不同。** 两者都叫「下载」但方向相反：
> M-17 是产物往外走、不需要授权；M-18 是文件往里走、每次都要授权。
> 建议 M-17 用 `LR` 单向发散、M-18 用带两个闸门的串行链，
> 让读者扫一眼就知道不是一回事。

### 第四部分

**M-19 控制台地图**（第 18 章）· `flowchart TB` + 6 个 `subgraph` · **全书唯一全景导航图**

**M-20 一个技能从哪来、到哪去**（第 19 章）· `flowchart LR`
`来源（内置 / 压缩包 / URL / 目录 / 页面临时）→ 安装 →（可能进审批队列）→
技能库 → 被对话使用 → 可导出`。

**M-21 从一次对话到一条运行记录**（第 20 章）· `flowchart LR`
对话里的一次提问 → 一条运行记录 → 展开为详情（时间线 / 工具调用 / 模型往返 / 产物）。

**M-22 一个新技能进入技能库的关口**（第 21 章）· `flowchart TD`
`候选技能 → 审批队列 →（通过 / 拒绝）→ 技能库 → 变更记入审计日志 → 出问题可回滚`。

**M-23 工具从哪儿来**（第 22 章）· `flowchart LR`
四个来源汇入「助手可用的能力」：技能库里的技能 / 你所在系统提供的页面工具 /
网页自带的 WebMCP 工具 / 远程 MCP 服务。解释连接组为什么是四页。

**M-24 设置项影响什么**（第 23 章）· `flowchart LR`
左列 8 个设置页，右列它们影响的用户可见行为，用连线对应。

### 第五部分

**M-25 一句话背后发生了什么**（第 24 章）· `sequenceDiagram`

```
sequenceDiagram
    participant U as 你
    participant A as 助手
    participant P as 页面工具
    participant S as 技能
    U->>A: 生成敏捷运营报告
    A->>P: 取需求数据
    P-->>A: 需求列表
    A->>P: 取迭代数据
    P-->>A: 迭代列表
    A->>S: 用报告技能汇总
    S-->>A: 报告
    A-->>U: 报告 + 可下载产物
```

参与者用**用户语言**命名，不要用组件名。

**M-26 从一句话到一份 PDF**（第 26 章）· `flowchart LR`
`提出需求 → 生成公文 → 对话里预览 → 打开文档 → 打印或存 PDF`。

**M-27 幻灯片的产生与放映**（第 27 章）· `flowchart LR`
`需求 → 生成幻灯片 → 请求开窗 →（你同意）→ 新窗口放映 → 翻页 / 导出 PDF`。
「你同意」是必经节点，不能省。

**M-28 一句话变成一条记录**（第 28 章）· `flowchart TD`
`你说一句话 → 它读懂 → 跳到对应页面 → 逐个字段填写（不打断你）→
【停】提交确认卡 → 你允许 → 写入成功`。
**「【停】提交确认卡」必须在视觉上突出**（加粗框或异色）——
整张图就是为了让读者看见这道刹车。
再从「你允许」引一条虚线到「也可以拒绝 → 这条不写入，但任务继续」。

**M-29 一份文件变成系统里的记录**（第 29 章）· `flowchart LR`
`选文件 → 【在你的电脑里】抽成文字 → 文字发给助手 → 它复述准备录什么 →
你确认 → 逐条填表 → 每条提交前确认 → 录入完成`。
**「【在你的电脑里】」要标注清楚**，图注写明"原文件没有整份发出去"。
这张图与 M-33（数据去向）结论必须一致。

**M-30 一个技能的一生**（第 30 章）· `flowchart TD`
`一次成功的对话 →（你说"存成技能"）→ 预览确认 → 进审批队列 →
审批通过并发布 → 可以调用了 → 用起来发现要改 → 改动（你改 / 它改）→
再次审批 → 生效 → 不满意 → 回滚到上一版`，
末尾画一条**回流边**指回「可以调用了」，体现这是个循环。
**本图取代原「M-28 一次技能改动的完整流程」**——原图只画了"改"，
缺了最前面的"从一次对话里长出来"。

### 第六部分

**M-31 能力边界示意**（第 31 章）· `flowchart TB` + 嵌套 `subgraph`
外圈「扩展版能触及的范围」内含内圈「网页版能触及的范围」，
外圈边缘标注约束（密码框不读、一次最多开多少页、授权可撤销）。
传达：**能力更大，但边界依然清晰**。

**M-32 排错决策树**（第 32 章）· `flowchart TD`
根「出什么问题了」→ 分叉到几大类症状 → 叶子指向本章对应小节。
放在章首代替目录。

**M-33 数据去向图**（第 33 章）· `flowchart LR` + 三个 `subgraph` · **最需要准确的一张**
三个区域：**留在本机**（会话、记忆、技能文件、设置、
**Word/Excel 的抽取过程**）、
**会发给模型**（你的提问、页面内容、工具结果、**从文档里抽出来的文字**）、
**永不外发**（密码框内容、**你上传的原始文件本身**）。
画完必须逐条核对依据，没有依据的项一律不放进图里。

## 4. 交付检查

每张图交付前确认：

1. `.mmd` 源文件已存 `.work/diagrams/`。
2. 含暗色 init 配置，渲染后无白底。
3. 节点名里没有任何代码符号（类名、函数名、包名）。
4. 有 `alt` 文本与图注，图注说明「该看出什么」。
5. 与相关章节的文字结论一致（尤其 M-03 与 M-11、M-14 与 M-33、M-29 与 M-33）。
6. 在 375px 宽度下不糊、不溢出（复杂图考虑改为纵向布局）。
