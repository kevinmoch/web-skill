# 04 · 拍摄手册

怎么把 [03-shotlist.md](03-shotlist.md) 里的图真的拍出来。
重点在**难拍的那些**——瞬时状态、异常态、扩展版。

---

## §1 环境准备

### 站点与 Demo

```bash
cd ~/Git/web-skill-site
pnpm dev            # 或 pnpm dev:sdk（源码档，界面与源码严格一致）
```

打开 `http://localhost:3000/demo`（**3000 被占用时会落到 3001，注意看终端输出**）。

推荐用 `pnpm dev:sdk`：它以 SDK 源码运行，
保证你在 `packages/**` 里读到的措辞就是屏幕上显示的措辞。

### 浏览器设置

| 项       | 设置                   |
| -------- | ---------------------- |
| 窗口     | 1440 × 900             |
| 缩放     | 100%                   |
| 书签栏   | 隐藏                   |
| 扩展图标 | 收起（拍浏览器全景时） |
| 通知     | 勿扰模式               |

### 录屏工具

批次 B、C、E、J 大量依赖**录屏后抽帧**。
macOS 用 `Cmd+Shift+5` 录制，或用任意支持逐帧导出的工具。
抽帧比连点截图键可靠得多。

## §2 Demo 数据预置

Demo 有 7 个屏（overview / requirements / sprints / bugs / tests / metrics /
webskill-manager）和内置数据，**开箱即用，不需要造数据**。

拍摄前确认：

1. 左侧选中一个数据完整的项目（数据太空的项目截图不好看）。
2. 13 个内置技能都已就位（技能中心 → 技能库能看到）。
3. 模型已配置（否则只有演示模型，部分能力拍不出来）。

> 技能是首次访问时播种的。若技能库是空的，
> 说明播种未执行或被跳过——清掉站点数据后重新访问即可重新播种。

## §3 预置多条会话（批次 D）

会话列表截图需要至少 5-6 条**标题各异**的会话，否则列表空荡荡。

做法：连续发起若干条不同主题的对话，每条只需一轮，
让标题自动生成即可。建议主题分散（报告、缺陷、页面总结、大屏、幻灯片…），
这样列表看起来真实。

再手动制造两种状态：

- 对其中一条执行 **重命名**，改成一个明显的自定义名字。
- 对另一条执行 **归档**，用于拍「已归档」标记。

## §4 抓瞬时状态（批次 B、C）

### 运行中状态（S-quickstart-03、S-chat-basics-01、S-transparency-01）

**录屏 → 抽帧**，不要试图手动抓。

选帧标准：

- 已经能看到至少一次工具调用，但整体还没结束。
- 状态条显示的是「执行工具」这类有信息量的阶段，不是刚开始的「路由中」。

想让运行慢一点便于取帧：选一个需要多次取数的提示词
（如「生成当前项目的敏捷运营报告，覆盖迭代健康、需求分布、缺陷热点和测试质量」），
它天然会有多轮工具调用。

### 删除后的撤销提示（S-chat-basics-05）

这个提示会自动消失，**必须录屏抽帧**。
操作：删除一条消息 → 提示出现的瞬间 → 抽帧。

### 消息操作栏（S-chat-basics-03、S-chat-tour-03）

操作栏通常悬停才出现。做法：鼠标悬停在消息上保持不动，再触发截图。
若截图工具会移动鼠标导致操作栏消失，改用录屏抽帧。

## §5 制造中断恢复横幅（S-chat-basics-06）

横幅文案：「你有一轮未完成的对话 / 上一轮运行在等待输入时中断。点击恢复，从中断处继续。」

**触发条件是"运行在等待输入时被中断"**，所以要：

1. 提一个会弹交互卡的需求（让运行停在「等待输入」阶段）。
2. 卡片出现后**不回答**，直接刷新页面或关掉重开。
3. 回来后横幅应出现。

若不出现，检查第 2 步是否真的停在了等待输入阶段——
运行已经结束的会话不会有横幅。

## §6 制造六种交互卡（批次 E，最难）

六种卡片：需要回答 / 请确认 / 需要补充信息 / 选择一个选项 / 需要授权 / 需要一个文件。

**第一步永远是读 `verify/agent/05-interactions.md`**——
它是为了验证这六种卡片而写的，里面有可用的触发路径。

```bash
cd ~/Git/web-skill-sdk && cat verify/agent/05-interactions.md
```

通用触发思路：

| 卡片                    | 触发思路                                                   |
| ----------------------- | ---------------------------------------------------------- |
| 需要回答 / 需要补充信息 | 提一个**故意缺少关键信息**的需求，让助手不得不问你         |
| 请确认                  | 提一个有副作用的操作                                       |
| 选择一个选项            | 提一个有多个候选目标的需求（如"打开那个项目"但有多个项目） |
| 需要授权                | 页面操作类需求（见 §8）                                    |
| 需要一个文件            | 让助手处理一个它手上没有的文件                             |

另需两张状态图：

- S-interactions-07（已提交后的只读形态）：回答完卡片后，卡片会变成记录形态。
- S-interactions-08（等待输入的运行状态）：卡片出现时运行状态条显示「等待输入」，
  与卡片一起入镜更好。

**如果某种卡片在 Demo 里始终触发不出来**：
不要伪造截图。在 `.work/` 里记录尝试过的方法，
改用扩展版或其他环境尝试；仍不行则在文档里如实描述该卡片但不配图，
并在验收报告里说明。

## §7 构造异常态（批次 J）

### 达到上限而停止（S-transparency-07）

最可靠的方法：**把上限调小**。

1. 控制台 → 设置 → 智能体运行时。
2. 把轮次上限调到一个很小的值（如 2-3）。
3. 提一个需要多轮工具调用的复杂需求。
4. 运行会因「达到轮次上限，运行已停止」而终止，此时截图。
5. **拍完把上限改回默认值**，否则后续所有拍摄都会被这个设置影响。

第 5 步很容易忘，记在 checklist 里。

### 被策略拒绝（S-transparency-04、S-actions-05）

需要构造一个越界请求。先读策略定义确认什么会被拒：

```bash
cd ~/Git/web-skill-sdk && cat packages/agent/src/pageAction/policy.ts
cd ~/Git/web-skill-sdk && cat packages/agent/src/tabs/policy.ts
```

按拒绝条件构造对应请求（例如请求操作不在允许范围内的目标）。
工具调用会显示「被策略拒绝」状态。

### 当前模型不接受图片（S-attachments-05）

切换到一个不支持图片的模型（模型能力标记会显示「不可传图片」），
然后尝试添加图片附件，提示即出现。

### 撞上工作集容量（S-tabs-06，仅扩展版）

助手一轮最多同时开 **32** 个页面，超出后会中途收尾。
要拍到这个状态，需要一个**超过 32 项的列表页**，
然后让助手逐项处理（「把这个列表每一项都打开看一遍，汇总给我」）。

找不到足够长的列表时，另一条路是**把容量调小**：
若宿主暴露了该设置就调到最小值（2），再给一个 4-5 项的列表。
Demo 未必暴露此项，先确认再决定走哪条路。

**拍完记得改回默认值 32。**

拍不到时如实标注，不要用别的截图冒充——
中途收尾的结果和正常完成的结果肉眼很像，冒充会误导读者。

## §8 触发页面操作（批次 G）

Demo 里 `navigate_to_screen` 是最稳定的页面操作工具——
它会让 Demo 切换屏幕，效果肉眼可见，适合拍「操作真的生效了」。

提示词思路：让助手带你去某个屏（如「帮我打开缺陷管理页面」）。

拍摄顺序（S-actions-01 → 03 是一组连续动作）：

1. 提出需求 → 授权卡出现 → 拍 S-actions-01。
2. 勾选/查看「记住」选项 → 拍 S-actions-02。
3. 点允许 → 页面切换 → 拍 S-actions-03（**前后对比图更好**：
   操作前后各截一张，并排放）。
4. 另起一轮，点拒绝 → 拍 S-actions-04。

## §9 扩展版拍摄（批次 K）

### 构建与加载

```bash
cd ~/Git/web-skill-sdk/examples/browser-extension
pnpm build
```

然后在 Chrome 里：`chrome://extensions` → 打开开发者模式 →
「加载已解压的扩展程序」→ 选择构建产物目录。

### 拍摄要求

**必须在真实扩展环境里拍，绝不能用网页版截图冒充。**
两者的界面外框不同（侧栏 vs 页面内抽屉），冒充会被一眼看穿。

| 图                | 场景要求                                                           |
| ----------------- | ------------------------------------------------------------------ |
| S-editions-02     | 侧栏助手 + 旁边是**任意第三方网页**（不是 Demo），体现"独立于网页" |
| S-perception-05   | 在一个普通网页上让助手读取内容                                     |
| S-tabs-01         | 浏览器全景：多个标签页 + 侧栏助手                                  |
| S-tabs-02/03      | 跨页取数的运行步进与汇总结果                                       |
| S-tabs-04         | 多步自动化过程（逐行处理列表）                                     |
| S-console-tour-05 | 扩展选项页形态的控制台                                             |
| S-attachments-06  | 麦克风/摄像头需在普通标签页授权的提示                              |

拍浏览器全景时**务必检查标签页标题与书签栏**，不要泄露无关信息。

### 多步自动化（S-tabs-04）

参考 `e2e-extension/tabWorkset.spec.ts` 里的场景：
一个列表页，让助手逐行进入详情、读取、返回、进入下一行。
找一个结构类似的公开网页，或用 Demo 的需求列表配合扩展版。
**全程录屏**，从中抽出能体现"它在自己翻页"的帧。

## §10 场景章的连贯拍摄（批次 B、H、L、M）

场景章（第 24-30 章）的截图**必须来自同一次连贯运行**，
否则数据对不上（比如报告里的缺陷数和截图里的列表对不上），读者会发现破绽。

做法：

1. 开始前**开录屏**。
2. 完整走完整个场景，中途不要切换项目、不要刷新。
3. 全程结束后从录屏里抽出该章需要的所有帧。
4. 抽帧后**逐张核对数据一致性**：同一个数字在不同截图里必须相同。

第 30 章（技能的一生）尤其要连贯：
**存成技能 → 待审 → 审批生效 → 用一次 → 改 → 再用一次 → 回滚**，
这是一条因果链，中间断了就证明不了闭环。

### 「它填、你批」的连续两帧（第 28 章，S-case-form-03 / 04）

这是全书**要求最严的一组截图**：它要证明"助手把表填满了，
但提交前停下来问你"。两帧之间**不能有任何别的操作**。

做法：

1. 录屏开着，用快捷提示「根据我的想法规划新需求、迭代任务和测试用例，
   带我到各个页面逐个创建落地」发起。
2. 助手开始填表时**不要动鼠标**——填写不弹确认卡，会一路填完。
3. 表填满、确认卡弹出的**那一刻前后各抽一帧**：
   前一帧 = 字段已满、无遮挡（S-case-form-03）；
   后一帧 = 同一张表 + 确认卡（S-case-form-04）。
4. 两帧的表单内容必须**逐字相同**，否则读者会看出是分开拍的。

S-actions-07（第 14 章）要的是**一张图里同时有已填字段和确认卡**，
可以直接用上面第 3 步的后一帧，**不必另拍**。

### 文档录入（第 29 章，S-case-import-\*）

素材用 Demo 自带的 `public/demo/attachment/*.docx`，
中英文都有，选与当前项目对得上的那份。

- S-case-import-01 要拍到附件小片上的**「文档正文」**字样，糊了就没意义。
- **拍之前先完整跑通一遍**。若换成自备的 `.xlsx`，
  必须实际跑通再拍，并在图注里注明是自备文件。
- 超长截断（S-case-import-06）可另起一次运行拍，
  找一份大文档触发即可，不必与主流程连贯。

### 「现成的 vs 现做的」对比图

S-skills-06、S-case-bul-05、S-case-slides-05 三张都是对比图，
证明**同一类需求、两种说法，走了不同的技能、得到不同的产物**。

拍法：**同一次会话里连续问两遍**，中途不换项目、不刷新。

```
第一句（笼统）：给我一份质量通报公文
第二句（限定）：只保留这个迭代的数据，把发布就绪度那段换成表格
```

两张图并排时，读者要能看出两处不同：
**消息上的技能标记名不同**，**产物内容/版式不同**。
技能标记必须在截图里可见——那是"确实换了技能"的唯一证据。

换会话拍会让人怀疑是别的因素造成的差别，**必须同一次会话**。

## §11 拍完之后

1. 按 [02-screenshot-spec.md](02-screenshot-spec.md) §8 逐张验收。
2. **脱敏复查**：设置页截图逐张放大检查密钥字段。
3. 压到 300 KB 以内（站点已有 `sharp` 依赖可用）。
4. 按命名规范入库到 `public/docs-assets/<slug>/`。
5. 更新 `.work/shotlist-progress.md`。
6. 在站点里实际渲染一遍，确认无碎图。

### 遗留项的处理

**拍不出来的图不要伪造、不要用示意图代替。**
在 `.work/shotlist-progress.md` 里标注为「无法拍摄」并写明尝试过的方法，
文档里该功能用文字描述，验收报告中如实列出。

诚实的缺图比伪造的截图代价小得多——
伪造的截图会让读者按图操作却找不到对应界面，直接摧毁文档可信度。
