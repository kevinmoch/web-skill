# 02 · 截图规范

截图是本次文档可信度的来源。**没有截图的功能描述不可信。**

---

## 1. 技术参数

| 项         | 要求                                          |
| ---------- | --------------------------------------------- |
| 设备像素比 | 2x（Retina），保证文字锐利                    |
| 浏览器窗口 | 1440 × 900（桌面截图统一）                    |
| 窄屏截图   | 375 × 812，用浏览器设备模拟                   |
| 格式       | PNG                                           |
| 单张体积   | ≤ 300 KB（超了用 `sharp` 压，站点已有该依赖） |
| 缩放       | 页面缩放必须 100%                             |

**同一章的所有截图必须来自同一次会话、同一个浏览器窗口尺寸**，
否则拼在一起会因字号/边距不同而显得杂乱。

---

## 2. 主题与语言

| 项                     | 要求                                       |
| ---------------------- | ------------------------------------------ |
| chatbot / console 主题 | **深色**（与站点暗色一致，视觉连贯）       |
| 界面语言               | 中文版文档用中文界面，英文版文档用英文界面 |

> **这意味着大部分截图要拍两遍**（中英各一套）。
> 拍摄时先把一种语言的全套拍完，再切语言重拍同样的场景，效率最高。
>
> 例外：不含文字的纯视觉图（如大屏效果）可中英共用，
> 在 shotlist 里标注为「共用」。

chatbot 自身支持浅色/深色切换（`header.theme.*`），
选**深色**是为了和站点暗色底一致，不是因为浅色不可用。

---

## 3. 内容规范

### 3.1 必须脱敏

截图前检查并清除：

- 真实的 API Key、Token、密钥（设置页截图重灾区，**必须逐张检查**）
- 真实姓名、邮箱、手机号
- 浏览器书签栏、其他标签页的标题（拍浏览器全景时尤其注意）
- 系统通知、聊天软件弹窗

**设置 → 大模型页的截图风险最高**，
必须确认密钥字段是掩码态或填的是明显的假值。

### 3.2 数据要真实且合理

用 Demo 的内置数据，不要手改成"完美数据"。
报告里出现"缺陷 0 个、覆盖率 100%"反而不可信。

### 3.3 状态要对

- 拍功能可用状态，不要拍加载中的骨架屏（除非该章就是讲加载）。
- 拍悬停才出现的元素（如消息操作栏）时，确保它真的显示出来了。
- 拍"运行中"状态时，进度要处在有代表性的中间态，不是刚开始的空白。

---

## 4. 标注规范

需要标注的截图（如第 4 章的界面分区全景）：

| 项     | 要求                                                     |
| ------ | -------------------------------------------------------- |
| 标注色 | 站点强调色 `#38bdf8`，在暗色底上清晰                     |
| 编号   | 圆形数字标 ①②③，配对照表                                 |
| 箭头   | 细线，不要粗箭头压住界面内容                             |
| 文字   | **不要在图上写中文说明**——图上只放编号，说明放正文表格里 |

最后一条很重要：图上写死文字会导致**英文版需要重做一套标注图**。
只放数字编号则中英共用一张图，说明在正文表格里各写一份。

---

## 5. 命名与存放

```
public/docs-assets/<slug>/<编号>-<简短英文名>.png
```

例：

```
public/docs-assets/chat-basics/S-chat-basics-02-stopped-content-kept.png
public/docs-assets/page-actions/S-actions-01-authorization-card.png
```

中英两套的区分：

```
public/docs-assets/chat-basics/zh/S-chat-basics-02-....png
public/docs-assets/chat-basics/en/S-chat-basics-02-....png
```

共用图（无文字）直接放 `<slug>/` 根下，不分语言目录。

---

## 6. 图注

每张截图必须有图注，写**这张图证明了什么**，不是描述图上有什么。

| ✅ 好图注                                          | ❌ 坏图注      |
| -------------------------------------------------- | -------------- |
| 点停止后，已经生成的正文完整保留，中止提示单独显示 | 停止按钮的截图 |
| 同一句话在缺陷屏问，助手总结的是缺陷数据           | 缺陷页面截图   |
| 授权卡上写明了要执行的操作和目标页面               | 如图所示       |

模型输出类截图的图注末尾加：
`示例运行结果，你的实际输出会有所不同。`

---

## 7. 无障碍

- 每张图必须有 `alt`，内容与图注一致或更详细。
- **图不能是唯一的信息载体**：图里传达的关键信息，正文必须也用文字讲一遍。
  纯靠截图说明的功能，屏幕阅读器用户完全无法获取。

---

## 8. 验收

交付前逐张确认：

1. 2x 清晰，无模糊、无锯齿。
2. 无敏感信息（**逐张过一遍，尤其设置页**）。
3. 主题为深色，语言与所在文档版本一致。
4. 文件命名符合规范，路径存在。
5. 有图注与 `alt`。
6. 中英两套齐全（共用图除外）。
7. 体积 ≤ 300 KB。
8. 在站点里实际渲染一遍，无碎图、无变形。
