# 出一份可打印的质量通报

用一句话让助手把当前项目的质量情况出成一份公文：发文单位、表格、结论、落款齐全，按 A4 排版，可直接打印或存成 PDF。这一章把技能、产物窗口和打印串成一次完整任务。

![从一句话到一份 PDF：提出需求 → 助手生成公文 → 在对话里预览 → 打开文档 → 打印或存成 PDF；提出修改会回到「重新生成一版」](/docs-assets/case-bulletin/M-26.svg)

## 开始之前

- 打开 [Demo](/demo)，左侧选定一个项目——通报取的就是它的数据。
- 确认页面右缘能看到助手入口。

## 第一步：提出需求

点欢迎页「试试这些示例」里的质量通报一条，或在输入框里粘贴：

```
为当前项目生成一份可打印的质量通报公文，包含缺陷趋势、测试覆盖和发布就绪度结论
```

这句话没限定范围也没提要求，助手会走「现成的」固定模板技能：快、稳，但改不动。现成的与现做的取舍见[技能：让助手会干专业活](#/docs/skills-usage)，不重复展开。

![对话里出现通报要点摘要和「打开文档」按钮](/docs-assets/case-bulletin/zh/S-case-bul-01-preview.png)

助手先简要总结通报要点，末尾给出 **打开文档** 按钮。示例运行结果，你的实际输出会有所不同。

## 第二步：打开文档看版式

点 **打开文档**。开窗前会弹一张「请确认」卡，写明谁要开窗、数据来自哪里，点 **确认** 才会打开（用意见[产物：大屏、公文、幻灯片与打印](#/docs/artifacts)）。

![通报在独立窗口中打开，红头、表格与落款完整](/docs-assets/case-bulletin/zh/S-case-bul-02-document.png)

它不是一段纯文字，而是排好版的公文：红头与期号、缺陷分级表、测试覆盖率表、DORA 四项指标、发布就绪度评分与结论、落款盖章。技能设定的版式（页边距等）在打印时会被保留。

## 第三步：打印或存成 PDF

1. 在文档窗口右上角点 **打印**——用这个按钮，不用浏览器菜单里的打印。
2. 在打印预览里核对版式。
3. 直接打印；要存成文件，把打印目标选成「另存为 PDF」。

![打印预览中的通报，A4 版式与屏幕上看到的一致](/docs-assets/case-bulletin/zh/S-case-bul-03-print-preview.png)

![存成 PDF 后的通报文件](/docs-assets/case-bulletin/zh/S-case-bul-04-pdf.png)

## 第四步：让它改一版

固定模板的口径是写死的：取整个项目的全量数据，版式一个字都改不了。想改就直接说，例如：

```
只保留这个迭代的数据，把发布就绪度那段换成一个表格
```

助手会换用「现做的」技能，重新取数、重新排出一版**新的**，而不是在原件上微调——技能标记也跟着换了名字。看到它整份重做，别以为它没听懂。

![提出修改后重新生成的第二版，技能标记与第一版不同](/docs-assets/case-bulletin/zh/S-case-bul-05-second-version.png)

更省事的是一开始就把要求说清楚：

```
为当前迭代生成一份质量通报公文，只要缺陷趋势和测试覆盖两部分，结论用表格
```

限定了范围、指定了结构，第一次就会走「现做的」。

## 换个说法也能做到

- 「给当前项目出一份能打印的质量通报」——最短说法。
- 「这个项目能不能发布？给我一份带数据依据的正式通报」——换种问法，产物相同。
- 第四步那句带范围带结构的——一开始就要定制版。

## 网页版与扩展版的差别

流程两者一致，差别在取数范围：网页版只取当前系统的数据；扩展版里「现做的」技能还能先读你打开的其他标签页再汇总（见[跨标签页工作](#/docs/tabs)）。

## 出问题了怎么办

**点了「打开文档」，窗口没出来。** 先看确认卡上是不是点了 **取消**；确认过仍没开窗，多半是浏览器拦了弹窗，允许后再点一次。

**我只说改一处，它却整份重做了一遍。** 这是固定模板的边界，不是故障：原件改不动，只能换「现做的」重做一版。想少跑一轮，一开始就限定范围、说清要求。

**通报里的数据范围和我想要的不一样。** 笼统地要，取的是整个项目的全量数据；只要某个迭代或某类缺陷，第一句话里就把范围说清楚。
