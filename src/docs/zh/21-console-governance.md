# 治理与复核

技能不是装上就一成不变的：新技能从哪来、谁批准的、每次改动记在哪里、改坏了怎么退回去——控制台「治理」分组下的五个页面管的就是这些事。

## 你能做什么

- 审批等审批的技能：逐字看过内容，再决定发布还是驳回
- 在审计日志里查「谁在什么时候改了什么」，这份记录改不掉
- 技能改坏了，回滚到上一个能用的版本
- 用评估任务把技能批量跑一遍，验证没有把它改坏
- 在洞察里看哪些技能常用、哪些疑似重复可以清理

## 五个页面串成一条线

你在对话里把一次成功的过程[存成技能](#/docs/skills-usage)后，它不会直接生效，而是作为等审批的技能进入**审批队列**；你审过、发布，它才进技能库。之后的每次编辑、发布、回滚都会记进**审计日志**；改坏了到**版本**页退回旧版；**评估**和**洞察**回答另两个问题：改完还稳不稳、哪些该清理。

![M-22 一个新技能进入技能库的关口：等审批的技能经审批队列发布或驳回，发布后进入技能库，每次变更记入审计日志，出问题可回滚到旧版本](/docs-assets/console-governance/zh/M-22.svg)

五个页面在控制台左侧导航的**治理**分组下，从上到下的顺序就是这条线：审批队列、审计日志、版本、评估、洞察。

### 审批队列（Review Queue）

**做什么用**：等审批的技能进技能库之前，在这里由人过目——新技能不会不打招呼就装进来。

**你在这里可以**：

- 按来源、按状态筛选队列里的条目
- 打开一条的详情，逐字检查它的风险理由和文件内容
- 点 **发布** 让它进技能库，或点 **驳回** 写下理由
- 删除不再需要的条目

每条都显示名称、状态（草稿 / 待审核 / 已批准 / 已发布 / 已拒绝）、来源与风险（高 / 中 / 低），可按来源和状态筛选。来源有四种：对话生成、文档、手动、运行时未命中；列表为空时，页面也会把这四个来路写清楚。

从对话里保存的技能，进来时状态是**草稿**——[保存时那张卡片](#/docs/skills-usage)上写的「已提交待审」，落在状态列就是草稿。草稿只有两个去向：发布，或删除。驳回是给「待审核」「已批准」的条目准备的，这两种状态正常流程里见不到，只在发布中途出错时残留。

审批一条：

1. 在控制台 **治理** → **审批队列**，点这条的 **查看详情**。
2. 核对 ID、来源、风险、创建时间；风险高的会把理由逐条列出（比如要联网、要往目录外写文件）。下方是这个技能每个文件的完整内容——将要发布的是什么，在这里逐字看。
3. 没问题，点 **发布**。一次点击就走完全部审批手续（草稿会自动补齐提交与批准），随后提示「已发布 ……——已安装、记录版本并写入审计」。
4. 不行就点 **驳回**：必须填驳回理由（输入框里的提示是「要发布的话得先改什么？」），不填按钮点不动，理由会留在记录里。驳回只对「待审核」「已批准」有效；**草稿**不能驳回，不要了就在列表里点 **删除**。

![审批队列列表：每条带状态、来源与风险徽章](/docs-assets/console-governance/zh/S-console-gov-01-review-queue.png)

![详情里逐条列出风险理由与文件全文，底部是「发布 / 驳回」](/docs-assets/console-governance/zh/S-console-gov-06-review-actions.png)

发布后立即生效：技能出现在[技能库](#/docs/console-skills)里，回对话就能用。对话里存技能时，卡片上的 **去审批** 会直接跳到本页并选中那一条（候选 ID 可复制）；那一条已不在队列时，页面会写明可能的去向（已通过、已拒绝或已被清理），不让你自己翻列表。

**常见用法**：让助手把这次做过的事改成技能，改出来的技能同样先到这里等你审，完整过程见[把这次做过的事变成一个技能](#/docs/case-skill-lifecycle)。

### 审计日志（Audit Log）

**做什么用**：谁在什么时候改了什么，这里有一份改不掉的流水账。

**你在这里可以**：

- 按类型、按操作者筛选事件
- 展开任意一行，看这次变更的细节
- 点 **校验链**，验证整份记录有没有被改动过

装技能、卸技能、发布、回滚、隔离、改安全与隐私策略、换模型配置……每个动作都记成一行：时间、事件、目标、操作者。事件列显示英文代号（如 `skill.published`）；中文说明在「按类型过滤」下拉里，每项都带（如 `skill.published（发布）`），那里也列全了所有事件类型，不用自己猜名字。点 **查看详情** 展开这一行的细节。

![审计日志：每行是一次变更，可按类型与操作者筛选](/docs-assets/console-governance/zh/S-console-gov-02-audit-log.png)

这份记录只增不改。点 **校验链**：「链完整」即完好；断在某一行时，页面会写明断点与原因，断点之前的记录仍然可见，提示里带 **重试** 入口。

**常见用法**：发现技能行为不对劲，先来这里查它最近被谁改过、改过什么，再决定要不要回滚。

> **注意**：日志只记「发生了什么」，不记敏感内容——改模型配置只记改了哪几项，密钥不会出现在日志里。技能的文件内容也不在日志里，要看去审批队列。

### 版本（Versions）

**做什么用**：每个技能改过的每一版都在这里，改坏了可以退回去。

**你在这里可以**：

- 看每个技能的版本历史，展开某一版看它包含哪些文件
- 回滚到任意一个还留着归档的旧版
- 查看技能状态，处理被自动隔离的技能

每次编辑、发布、回滚都会追加一个版本条目，带时间、原因、大小；点 **查看归档** 能看到那一版包含哪些文件。页面上写明保留策略：每个技能保留最近 5 个版本。系统自带的技能没有版本记录时，页面会明确说明，不是一片空白。

回滚到上一版：

1. 在 **治理** → **版本** 选中技能，在版本列表里找到要回的版本，点 **回滚**。
2. 弹窗会再确认一次：旧版本的文件要先通过校验才会动手，任何失败都会完整恢复当前文件。
3. 看到「已回滚到 ……」后，回对话再用一次这个技能，行为就是旧版的样子——不是只改个版本号。

![回滚有二次确认，并写明校验与恢复行为](/docs-assets/console-governance/zh/S-console-gov-07-rollback.png)

![版本页：版本历史与技能状态在同一页](/docs-assets/console-governance/zh/S-console-gov-03-versions.png)

同一页下方是**技能状态**：连续失败达到阈值（默认 5 次，页面上写明）的技能会被自动隔离（状态 quarantined），助手不再调用它。隔离原因直接显示——「连续失败 N 次」和「完整性校验未通过」（文件被改过）分得清；被安全策略拒绝不算失败。点 **诊断** 可让助手分析最近一次失败并给出修复计划，认可哪条点哪条的 **执行**；也可以在状态下拉里改回 active。隔离不会因为碰巧成功一次就自动解除。

页面底部是 **运行时未命中钩子** 开关：打开后，助手遇到没有技能会干的事时，会自动起草一个等审批的技能放进审批队列——来源为「运行时未命中」的条目就是这么来的。

**常见用法**：升级过的技能不如旧版好用，选中它，点旧版的 **回滚** 退回去。

### 评估（Evaluation）

**做什么用**：改完一个技能不放心，用它批量跑一组任务，看结果稳不稳。

**你在这里可以**：

- 添加、删除评估任务
- 点 **全部执行** 跑整组，看通过率与逐条结论
- 把一个失败运行变成长期的回归任务

每条任务有三项：`Prompt`（一句指令）、期望子串（可选）、技能（可选，逗号分隔）。点 **全部执行** 跑整组，按钮上显示进度（执行中 x/3）。跑完出报告：通过率、平均分和逐条结论；没通过的能看到期望与实际的差别，并能点回那次运行的详情。

![评估页：任务列表、「全部执行」与最近报告；报告内容是一次真实运行的示例，你的实际结果会有所不同](/docs-assets/console-governance/zh/S-console-gov-04-evaluation.png)

**回归建议**很实用：从[运行记录](#/docs/console-runs)复制一个失败运行的 ID，粘进输入框点 **生成并加入**，它会照那次失败生成一条新任务，以后每次评估都替你盯着这个坑。

**常见用法**：改完技能，把它相关的几条任务重跑一遍，通过率没掉再放心用。

> **注意**：「全部执行」会真的调用模型去跑技能，所以要先配好一个可用的模型；没配的时候按钮是灰的，页面上有说明。配模型见[连接](#/docs/console-connections)。

### 洞察（Insights）

**做什么用**：哪些技能常用、哪些疑似重复可以清理，这页给你一份体检表。

**你在这里可以**：

- 看每个技能的评分卡与改进建议
- 发现疑似重复的技能对，考虑合并
- 用使用统计找出从没被用过的技能

**技能评分**：每个技能一张评分卡，综合分加四个维度条（成功率 / 使用量 / 评估分 / 风险），并给出建议（保留 / 改进 / 合并 / 弃用 / 隔离）。页面上注明「仅覆盖受管技能」：走安装流程、留有安装记录的技能才参评；系统自带的技能没有安装记录，风险一项无从算起，就不参与——原因也写在页面上。

**疑似重复**：名称与描述高度重叠的技能对会列在一起，带相似度，并建议把两者合并为一个。

**依赖图**：点一个节点就能看到「删除它会影响到谁」；没人依赖会明说。删技能之前先看这里。

**使用统计**：每个技能的激活、成功、失败次数，图表分成功、失败两个系列。

## 网页版与扩展版的差别

五个页面本身两者一致：同样的审批、审计、版本、评估、洞察。差别只在入口——网页版从你所在网站内部的管理页进入（Demo 里点对话头部的 **设置**），扩展版在扩展的选项页里，打开时可直达某个分区。两边各管各的技能库与记录。入口细节见[控制台导览](#/docs/console-tour)。

## 出问题了怎么办

**点了「去审批」，页面却说那条已经不在了。** 它可能已被批准、被驳回或被清理，页面会写明可能的去向。先到[技能库](#/docs/console-skills)看看它是不是已经能用了。

**「全部执行」是灰的。** 批量评估要真的调用模型，你还没配可用的模型。到 **连接** → **大模型** 配一个，见[连接](#/docs/console-connections)。

**想回的版本点不了「回滚」。** 页面会写明「该版本没有保留归档，无法回滚」——这一版的文件没留下来，退不回去。每个技能只保留最近 5 个版本，重要版本别拖太久才决定。

**技能突然调不动了。** 多半是连续失败被自动隔离。到 **版本** 页下方看状态和隔离原因，点 **诊断** 拿修复建议；确认没问题后在状态下拉里改回 active。如果只是工具调用显示「被策略拒绝」，那不计入失败、也不会导致隔离——是权限问题，见[设置](#/docs/console-settings)。

**审计日志提示链断了。** 记录文件被改动过或已损坏。断点之前的记录仍然可信、仍然展示；点提示里的 **重试** 重新查询，再点一次 **校验链** 确认位置。断点之后的事件不会再展示，因为它们已无法验明真伪。
