# 看懂助手在做什么

助手进行到哪一步、动了什么、为什么停下来，都直接显示在对话里。看懂了，你就知道什么时候该等、什么时候该插手、出了问题去哪查。

## 你能做什么

- 从运行状态一眼看出助手是不是还在干活
- 展开**运行流程**，回看每一步做了什么
- 查看每次工具调用的状态和参数
- 用**任务清单**跟踪长任务的进度
- 看懂运行停止的原因，知道接下来怎么办
- 复制**运行 ID**，在控制台的运行记录里精确定位这次运行

## 一次运行分几个阶段

消息发出后，回答区域先显示**思考中…**，表示运行开始了。展开**运行流程**卡片，能看到按下面顺序推进的每个阶段：

| 阶段名 | 助手在做什么 |
| --- | --- |
| 路由 | 判断该用哪个技能或工具 |
| 激活 | 已选定技能，正在装载它 |
| 执行 | 真的在干活：查数据、读页面、生成内容 |
| 交互 | 停下来，等你回答一张卡片 |
| 完成 | 正常结束 |
| 失败 | 异常结束（含被你中止），具体原因见下文「它为什么停了」 |

两点要先知道：

- 阶段会循环。执行完一批工具后会回到**路由**，再判断下一步。复杂任务里来来回回几次是正常的。
- 看到阶段停在**交互**，不是卡住了，是在等你。往上翻一翻，找到那张还没回答的卡片。

![运行中的状态区，显示「思考中…」](/docs-assets/transparency/zh/S-transparency-01-status-bar.png)

「思考中…」表示运行已经开始；进行到哪个阶段，展开运行流程看。

![M-11 一次运行的阶段流转](/docs-assets/transparency/zh/M-11.svg)

执行之后可能回到路由；任何阶段都可能走向失败（含你主动中止）。

## 运行流程：每一步都看得见

「思考中…」只告诉你助手在干活。展开**运行流程**卡片，里面按顺序列出这次运行的每一步；激活了技能时，会出现「激活 <技能名>」这样一步，右侧带耗时。

![M-12 运行界面的信息层次](/docs-assets/transparency/zh/M-12.svg)

细节是一层层展开的：运行状态看「思考中…」，运行流程看每一步，再点开单步看参数。

![运行流程展开后的完整步骤列表](/docs-assets/transparency/zh/S-transparency-02-run-steps.png)

每一步都有据可查。示例运行结果，你的实际输出会有所不同。

## 工具调用：它动了什么

工具是助手能执行的一个具体动作，比如「读取需求列表」「跳转到某个页面」，由你所在的系统提供。运行区会显示「{count} 次工具调用」。每次调用占一行：状态图标加工具名，行右侧是耗时；点开这一行能看到**参数**。

每次调用有四种状态：

- **运行中**：正在执行。
- **已完成**：成功，有结果。
- **失败**：没执行成。失败的调用会自己展开，附上**失败原因**。助手通常会换个办法继续，看到一次失败不必紧张。
- **被策略拒绝**：这次调用根本没有执行。

「被策略拒绝」值得多说一句：你所在的系统给助手划了安全边界，比如不许碰某些数据、不许做某类操作。触到边界的调用会被直接拦下，并附上**拒绝原因**。这不是出错，而是边界在工作——它说明不是所有请求都会被执行。

![单次工具调用展开后的参数区](/docs-assets/transparency/zh/S-transparency-03-tool-detail.png)

展开一次调用能看到它的参数；耗时显示在每一行的右侧。示例运行结果，你的实际输出会有所不同。

![显示「被策略拒绝」状态的工具调用](/docs-assets/transparency/zh/S-transparency-04-policy-blocked.png)

被拦下的调用会标明「被策略拒绝」并给出拒绝原因。

## 思考过程

助手组织思路时，回答区域会出现标题为**思考中…**的折叠区。点开可以读到它这一段的思考内容——当你怀疑它理解偏了你的意思，先看这里。运行结束后它会自动收起，可随时再展开。

![运行中的思考过程折叠区，标题为「思考中…」](/docs-assets/transparency/zh/S-transparency-05-thinking.png)

思考内容可以展开阅读。示例运行结果，你的实际输出会有所不同。

## 任务清单：长任务的进度

复杂任务会被拆成一份**任务清单**，每一项有三种状态：**待开始**、**进行中**、**已完成**，标题旁的进度数字 `{done}/{total}` 告诉你做完了几项。

有的条目会显示「已委派给 {技能名}」。看到这行不用意外，记住三点：

1. **这是它自己在分工。** 复杂任务里，助手会把某一步交给一个更专门的技能去做。你不需要做任何事。
2. **是一步一步来的，不是同时开工。** 派出去的那一步做完，它才继续下一步。所以看到「已委派」时，等就对了。
3. **有一个副作用要知道。** 派出去做的那部分，不算作本次对话里做过的步骤。因此用「把对话存成技能」时，带「已委派」条目的对话可能存不上（见[技能：让助手会干专业活](#/docs/skills-usage)）。遇到时的做法：不让它派活，自己重做一次关键步骤再存。

![任务清单，含进行中与已完成的条目](/docs-assets/transparency/zh/S-transparency-06-todo-list.png)

每一项的状态和标题旁的进度数字都直接可见。示例运行结果，你的实际输出会有所不同。

## 它为什么停了

运行提前结束时，界面会给出一句原因。对照下表处理：

| 界面提示 | 含义与你可以怎么做 |
| --- | --- |
| 运行已被你中止 | 你自己点了停止。无需处理，想继续就重新发一次。 |
| 达到轮次上限，运行已停止 | 「轮次」是助手思考加执行的一个来回，默认上限 1000 轮。触顶说明任务太复杂：把它拆成几步，分几次说。上限可以在设置里调大，触顶的错误卡上有按钮直接跳到那页设置。 |
| 达到时长上限，运行已停止 | 默认上限 3600 秒（1 小时）。处理办法同上：先拆任务，不够再调设置。 |
| 模型请求失败，运行已停止 | 多半是网络或模型配置问题。检查网络；如果你自己配过模型，按[选择模型](#/docs/models)一章检查配置。 |
| 表单未及时提交，运行已停止 | 助手弹出的卡片等你有时间限度（默认 5 分钟），超时运行就结束了。看到卡片尽快回答；来不及就重发一次。 |
| 生命周期钩子失败，运行已停止 | 不是你做错了什么，是系统内部的检查环节出了错。联系提供这个系统的人。 |
| 多次调用不存在的工具，运行已停止 | 它反复试图用一个不存在的工具，多半是当前技能和这个页面对不上。换个说法重试；仍不行就确认要用的技能已启用。 |
| 运行未正常结束 | 兜底提示，原因不明。先重试；反复出现就复制运行 ID，到[运行记录](#/docs/console-runs)里查。 |

![因达到上限而停止的提示](/docs-assets/transparency/zh/S-transparency-07-limit-reached.png)

触顶停止的提示会说明是哪个上限、当前值是多少、去哪里改。

## 查看追溯与运行 ID

每次运行都有唯一的**运行 ID**，展开**运行流程**卡片就能看到，点**复制运行 ID**即可复制。把它拿到控制台的[运行记录](#/docs/console-runs)里搜索，能精确定位这次运行的完整记录。

![运行 ID 与复制按钮](/docs-assets/transparency/zh/S-transparency-08-run-id.png)

复制下来的运行 ID 是排查问题时最重要的线索。

## 网页版与扩展版的差别

显示项两者一致：运行状态、运行流程、工具调用、任务清单、终止提示都一样。差别在步骤内容：扩展版可以跨标签页工作，步进里可能出现对其他标签页的读取和操作；网页版的步骤只涉及当前站点。

## 出问题了怎么办

- **运行停着不动，像是在等什么。** 往上翻，找到没回答的卡片，回答后运行会继续。放太久不答，运行会以「表单未及时提交，运行已停止」结束。
- **经常触到上限。** 到控制台[设置](#/docs/console-settings)里把上限调大，改动对下一次运行生效；那页还有「恢复默认」可以还原。调大只是兜底，先试试把任务拆成几步说。
- **工具调用「被策略拒绝」。** 这是安全边界拦住了这次操作，先看旁边的拒绝原因；确实需要这个操作时，联系提供系统的人调整策略。
- **看不懂某次运行为何失败。** 复制运行 ID，连同你看到的现象一起发给提供系统的人，比在对话里反复重试有效。
