# 技能管理

技能是一份打包好的「做某件事的说明书 + 脚本」，装上之后助手就会干这件事。而装上之后的事都归这一章管：从哪装的、最近用没用过、想改内容、文件有没有被动过。控制台「技能」分组的四个页面，正好对应这四件事。

## 你能做什么

- 在技能库看全部已安装技能：来源、版本、最近什么时候被用过
- 在编辑器里查看和修改技能文件，保存时自动校验，写错当场告诉你
- 从压缩包、网址或文件夹安装新技能，确认预览之前什么都不写入
- 把技能打包导出给别人；不需要了可以卸载
- 逐文件校验技能内容，确认它还是你装时的样子

## 技能从哪来、到哪去

![一个技能从哪来、到哪去：预装、压缩包、网址、文件夹、页面临时提供，经安装（可能先经审批）进入技能库，被对话使用，还能导出带走](/docs-assets/console-skills/zh/M-20.svg)

技能有几个来源：系统预装的（Demo 里是 13 个内置技能）、你自己从压缩包、网址或文件夹装的、页面临时提供的。前两类装好后进技能库，对话里就能用，还能导出带走；页面临时提供的不进技能库，离开页面就没了，见[连接](#/docs/console-connections)。另有一个例外：助手帮你生成或改出来的技能不直接进库，会先成为等审批的技能排在审批队列里，审过发布才生效——见[治理与复核](#/docs/console-governance)。13 个内置技能各自能干什么，见[技能：让助手会干专业活](#/docs/skills-usage)。

## 四个页面

### 技能库（Library）

**做什么用**：装了哪些技能、各自从哪来、最近在什么时候派上过用场。

**你在这里可以**：

- 在过滤框输关键词，按名称和描述同时筛选——输「幻灯片」，做幻灯片的两个技能就都出来了
- 看每行的标记：「来源」说明它从哪来；「受管」表示它由包管理器看管，只有受管技能能卸载、重命名、逐文件校验
- 看「最近使用」一列，哪个技能很久没用上一目了然
- 点技能名进编辑器；行尾菜单里有「在编辑器中打开」「导出」，受管技能多出「校验完整性」「重命名」「卸载」
- 点「模型上下文」看助手实际能看到的技能清单——它和这页列表一致，助手「不知道」某个技能时先来这核对

![技能库一页看全 Demo 的 13 个内置技能，含来源、内容构成与最近使用](/docs-assets/console-skills/zh/S-console-skills-01-library.png)

**常见用法**：想知道「做大屏的技能叫什么、最近什么时候用过」，过滤框输「大屏」就能看到一对技能——一个现成的、一个现做的；用哪个由助手按你的话判断，区别见[技能：让助手会干专业活](#/docs/skills-usage)。

### 编辑器（Editor）

**做什么用**：查看和修改技能里的文件。保存时自动校验，写错了当场列出，改对之前存不上。

**你在这里可以**：

- 左边文件树选技能、选文件；选中文件夹时，右边是它的文件清单和新建入口
- 新建、删除文件和文件夹；删除有确认，删掉 SKILL.md 这类关键文件会被拦下并说明理由
- 改完点「保存并校验」：通过显示「已保存并校验」；没通过会在下方列出「校验问题」，逐条改掉再存

技能的主文件叫 SKILL.md，内容就是一份说明书：什么时候用它、需要什么输入、分几步做。以内置技能 `sprint-weekly-brief` 为例：

```markdown
---
name: sprint-weekly-brief
description: 用周报模板输出当前迭代的进展简报——结构固定，数据自动填充。
---

## 何时使用

当用户要求迭代周报、迭代小结，或当前迭代的结构化进展汇报时使用。
```

![编辑器：左边是技能文件树，右边是 SKILL.md 的内容](/docs-assets/console-skills/zh/S-console-skills-02-editor.png)

![保存时校验未通过：「校验问题」逐条列出，改对之前存不上](/docs-assets/console-skills/zh/S-console-skills-05-save-validation.png)

「何时使用」这类段落就是助手挑选技能的依据。不想自己动手改，也可以交给助手：它改完的技能会成为等审批的技能，先审后用，完整过程见[把这次做过的事变成一个技能](#/docs/case-skill-lifecycle)。

### 安装与导出（Install & Export）

**做什么用**：把外面的技能装进来，或把自己的技能打包发给别人。

安装有三种来源，任选其一：

1. **归档 URL**：粘贴压缩包网址。默认只接受 https、拒绝内网地址，这个限制在「设置 › 沙箱与安全」里调整，见[设置](#/docs/console-settings)。
2. **本地 .zip 文件**：把压缩包拖进来，或点「选择 zip」。
3. **技能文件夹上传**：选中一个文件夹，浏览器会自己打成包。

![三种安装来源：网址、本地压缩包、文件夹](/docs-assets/console-skills/zh/S-console-skills-06-install-sources.png)

不管哪种来源，点「预览并安装」后都先出一份「安装预览」：包里有哪些文件、「安装前预检」过了几项，逐条列给你看。确认预览之前不会写入任何内容；预检有没通过的项，「安装」按钮就是灰的；根本不是有效压缩包的文件，连预览都进不去。

![安装预览：归档内容与安装前预检逐条列出](/docs-assets/console-skills/zh/S-console-skills-03-transfer-preview.png)

> **注意**：安装技能等于把别人写的脚本引进来运行。签名是作者给包盖的章，用来证明它没被掉包；预览里出现「归档没有签名。只有在你信任它的来源时才装。」这条警告时，先确认你信得过出处，再勾选确认继续。没签名的技能是放行、提醒还是拒绝，以及信任哪些签名者，都在「设置 › 信任与签名」里管，见[设置](#/docs/console-settings)。

装一个重名技能是受支持的升级流程：预览会提醒已有同名技能、装上会覆盖它；旧版留在版本历史里，可以回退，见[治理与复核](#/docs/console-governance)。

下方「已安装技能」列表可以逐个「导出」「卸载」，也可以勾选多个后点「导出技能包集」，把几个技能打成一个包整体分发。导出就是浏览器直接下载压缩包；卸载有二次确认，确认后不可撤销。

**常见用法**：同事发来一个技能压缩包，拖进来、看预检全过、点安装。装完它出现在技能库里，对话里直接能用。

### 完整性与清单（Integrity & Manifest）

**做什么用**：回答一个问题——我装的技能，还是原来那个吗？

**你在这里可以**：

- 选中一个技能，自动逐文件校验，汇总成「N 个文件通过 · N 个已修改 · N 个缺失 · N 个多出」；结果异常就点「重新校验」再核一次
- 每个文件的结果只有四种：通过、已修改、缺失、不在清单
- 看签名状态：「已签名且验证通过」「未签名」「验签失败」，带签名的还能看到签名者与签名时间
- 翻「安装账本」：每个技能什么时候、从哪里装的都记在里头

![完整性与清单：逐文件校验结果与安装账本](/docs-assets/console-skills/zh/S-console-skills-04-integrity.png)

什么时候该来看：技能行为突然不对劲，或刚从一个不太熟的来源装过技能。两条规则可以让你安心：

- 你在编辑器里改的不算异常——保存时记录会同步更新，再校验照样全部通过。只有绕过编辑器动文件，才会报「已修改」。
- 校验出问题的技能会被隔离：不被命中、不被执行，这页会显示「已隔离」及原因和时间。

## 网页版与扩展版的差别

四个页面的功能两者一致：同样的技能库、编辑器、安装与校验。差别只在控制台怎么打开——网页版从你所在网站内部的管理页进（Demo 里点对话头部的「设置」），扩展版在扩展的选项页里，详见[控制台导览](#/docs/console-tour)。

## 出问题了怎么办

**「安装」按钮是灰的。** 逐条看安装预览里的「安装前预检」：不是有效压缩包、SKILL.md 内容不全，或信任策略不允许未签名技能，都会拦在这一步。前两类要换一个没问题的包；签名相关的到「设置 › 信任与签名」调整，见[设置](#/docs/console-settings)。

**装完了，对话里却调不到。** 先到技能库确认它在不在；再去「完整性与清单」页看「依赖环」「依赖缺失」两节——那里列出的是被排除出技能目录的技能：依赖没装、或依赖关系绕成了圈，助手看不到它们，技能库里也不出现，这一页是唯一能看见它们的地方。把缺的依赖装上、把环解开，就恢复了。

**校验报「已修改」，是不是被人动过？** 先回想你或同事有没有在编辑器之外动过它的文件——在编辑器里改的不算。确认不是你改的，把这个技能卸载，从信得过的来源重装一次。

**保存点不动、存不上。** 保存即校验：写错了会在「校验问题」里逐条列出，改对了才能存上。删除 SKILL.md 这类关键文件同样会被拦下并给出理由——这是防止把技能改残，不是故障。
