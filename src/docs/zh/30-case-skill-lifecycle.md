# 把这次做过的事变成一个技能

你带着助手把一件事做成了，可以把这个过程存成技能：审过、发布后，下次一句话就能重跑；用起来不满意，还能再改、能退回旧版。这一章按同一次连贯操作，把一个技能的一生完整走一遍。

## 开始之前

- 打开 [Demo](/demo)，左侧任选一个项目，再切到 **缺陷管理** 屏——本章那条快捷提示只在这一屏出现
- 确认页面右缘能看到助手入口
- 确认「技能自动生成」开着：控制台 → **设置** → **智能体运行时**，Demo 默认开、出厂默认关；关着时第一步的入口不会出现，见[设置](#/docs/console-settings)

一个技能的一生不是一条直线，是个循环：

![M-30 一个技能的一生：对话存成技能，经预览确认进审批队列，审批通过发布后就能调用；发现要改，改完再生效；不满意回滚到上一版，回到「可以调用了」继续循环](/docs-assets/case-skill-lifecycle/zh/M-30.svg)

回滚后技能仍在技能库里继续被用，所以图末尾有一条指回「可以调用了」的回流线。

## 第一步：把这次对话存成技能

Demo 欢迎页「试试这些示例」里有一条现成的快捷提示，原样点用：

`先列出当前项目的缺陷清单，再读取本项目的 DORA 指标，然后把「查缺陷、读指标」这个流程固化成一个技能`

它会先让助手把这件事真做一遍——列缺陷清单、读 DORA 指标，再触发「存成技能」。助手弹出一张确认卡，原文是「将本次对话保存为技能「{name}」？」，下方写着：**它将提交审核，不会直接启用。请逐字检查下方预览，确认没有不应被保存的内容。**

这句责任提示是写给你的：对话里可能有不该长期保存的东西——具体的人名、内部数字、一次性的口令。逐字确认没有，再点保存。

![「保存为技能」确认卡，将要保存的技能内容完整预览](/docs-assets/case-skill-lifecycle/zh/S-case-life-01-save-confirm.png)

保存后提示：`「{name}」已提交待审。审批并发布后才能使用。`——存下来不等于能用，它进的是审批队列。卡片上给出候选 ID：点 **复制候选 ID** 复制，或点 **去审批** 直接跳到审批队列。

![提交后的「已提交待审」提示，含候选 ID 与「去审批」入口](/docs-assets/case-skill-lifecycle/zh/S-case-life-02-candidate-submitted.png)

> **注意**：这轮对话的任务清单里有「已委派给…」条目时，可能存不上——派出去的步骤不算本次对话的步骤。做法：不让它派活，关键步骤重做一次再存。缘由见[看懂助手在做什么](#/docs/transparency)。

## 第二步：审批并发布

点 **去审批** 直接落到审批队列并选中那一条。

1. 点 **查看详情**，下方是这个技能每个文件的完整内容——将要发布的是什么，在这里逐字看。
2. 没问题，点 **发布**。一次点击走完全部审批手续，随后提示「已发布……——已安装、记录版本并写入审计」。

![审批队列里这条等审批的技能，详情中逐字列出文件全文](/docs-assets/case-skill-lifecycle/zh/S-case-life-03-review-queue.png)

发布后立即生效：技能出现在技能库里，回对话就能用。

![发布成功，提示已安装、记录版本并写入审计](/docs-assets/case-skill-lifecycle/zh/S-case-life-04-published.png)

驳回、筛选等完整规矩见[治理与复核](#/docs/console-governance)。

## 第三步：用新技能跑一次

回对话发一句自然语言，比如 `查一下当前项目的缺陷清单和 DORA 指标`。助手消息上的「技能」标记显示的就是刚发布的它——前半段闭环：存下来的技能真的能用。

![用新技能跑一次，消息上的技能标记正是它](/docs-assets/case-skill-lifecycle/zh/S-case-life-05-run-with-skill.png)

示例运行结果，你的实际输出会有所不同。

## 第四步：改这个技能

用了一阵觉得要改——比如让它把指标解读写得更细。两条改法：

- **你自己改**：控制台 → **技能库** → 点技能名进**编辑器**，改完点「保存并校验」，存上就生效。
- **让助手改**：对话里说清要改什么，改完进审批队列等你审——改动不会不打招呼就生效。

![编辑器里修改这个技能，保存时给出校验结果](/docs-assets/case-skill-lifecycle/zh/S-case-life-06-editor-save.png)

「校验问题」的逐条说明见[技能管理](#/docs/console-skills)，审批怎么走见[治理与复核](#/docs/console-governance)。

## 第五步：用改后的技能再跑一次

再发一次同样的话，结果里能看出改动——后半段也闭环了：改动真的生效了，不是只改了个文件。

![用改后的技能跑一次，结果体现了刚才的改动](/docs-assets/case-skill-lifecycle/zh/S-case-life-07-run-after-edit.png)

示例运行结果，你的实际输出会有所不同。

## 第六步：不满意就回滚

改完不如旧版好用，退得回去：控制台 → **治理** → **版本**，选中这个技能，找到要回的版本点 **回滚**，确认后看到「已回滚到……」。回对话再用一次，行为就是旧版的样子——不是只改个版本号。每个技能只保留最近 5 个版本，二次确认与失败恢复的细节见[治理与复核](#/docs/console-governance)。

![版本页回滚到上一版，带二次确认](/docs-assets/case-skill-lifecycle/zh/S-case-life-08-rollback.png)

回滚不是终点——这个技能继续被用、被改、留下新版本记录，正是图上循环的一环。

## 换个说法也能做到

「存成技能」不靠固定咒语，换个说法表达同一个意图，也会引出同一张确认卡：

- `把刚才这个流程存下来，以后直接能用`
- `这个查法我以后每周都要用，做成技能吧`

关键只有一个：说清「把这次做的留下来、下次重跑」。

## 网页版与扩展版的差别

整条流程两者一致：存、审、用、改、回滚没有形态差别。差别只在控制台入口——网页版从你所在网站内部的管理页进（Demo 里点对话头部的 **设置**），扩展版在扩展的选项页里；两边各管各的技能库与审批记录。

## 出问题了怎么办

**点「去审批」却说那条已经不在了。** 它可能已被批准、驳回或清理，页面会写明去向；先到技能库看看它是不是已经能用了，见[技能管理](#/docs/console-skills)。

**编辑器里保存点不动。** 保存即校验：「校验问题」会逐条列出，改对才存得上——这是防止把技能改残，不是故障。

**想回的版本点不了「回滚」。** 页面会写明「该版本没有保留归档，无法回滚」——这一版的文件没留下来，退不回去。
