# 生成一份敏捷运营报告

用一句话让助手把当前项目的迭代健康、需求分布、缺陷热点和测试质量汇总成一份报告。这一章把前面学到的技能、运行流程和产物下载串成一次完整任务，全程可以在 [Demo](/demo) 里照着做。

## 开始之前

- 打开 [Demo](/demo)，左侧选中一个项目，比如**智云协同核心业务平台**——报告取的就是「当前项目」的数据。
- 新会话的消息区是欢迎页，「试试这些示例」里就有本章要用的那句话；也可以自己在输入框里敲。

## 第一步：提出需求

在欢迎页点下面这条快捷提示（或原样敲进输入框），按回车发出：

```
生成当前项目的敏捷运营报告，覆盖迭代健康、需求分布、缺陷热点和测试质量
```

它会触发什么：助手判断这句话要出报告，于是激活一个技能——一份打包好的「做某件事的说明书 + 脚本」，装上之后助手就会干这件事。这里激活的是 agile-ops-dashboard，它专做敏捷运营报告。

![提问时刻：欢迎页里的这条快捷提示](/docs-assets/case-report/zh/S-case-report-01-prompt.png)

## 第二步：看助手怎么干

发出之后，展开**运行流程**——这一章最值得看的就是它。「激活 agile-ops-dashboard」这一步后面跟着一串工具调用。工具是助手能执行的一个具体动作，由你所在的系统提供；报告里的每个数字都来自其中一次调用：

| 这次调用 | 它取回的数据 |
| --- | --- |
| `list_sprints` | 当前项目的迭代列表 |
| `list_requirements` | 需求条目及其状态 |
| `list_bugs` | 缺陷清单及严重度 |
| `list_test_suites` | 测试套件、覆盖率与通过率 |

![运行流程展开后，能看到一串取数的工具调用](/docs-assets/case-report/zh/S-case-report-02-run-steps.png)

一句话背后，助手分别查了四类数据再汇总。示例运行结果，你的实际输出会有所不同。

再点开其中任何一次调用，能看到它带了什么参数、取回了什么内容：

![单次工具调用展开后的参数与结果](/docs-assets/case-report/zh/S-case-report-03-tool-detail.png)

所以报告不是助手编出来的：每个数字都能回溯到一次真实查询。示例运行结果，你的实际输出会有所不同。

![M-25 一句话背后发生了什么](/docs-assets/case-report/zh/M-25.svg)

你说一句话，助手分多次向页面工具取数，交给报告技能汇总，最后把报告交回给你。阶段名、工具状态这些界面元素的完整说明，见[看懂助手在做什么](#/docs/transparency)。

## 第三步：拿到结果

报告直接画在对话里：迭代健康、需求分布、缺陷热点、测试质量各占一块，助手再补一两句头条结论。

![对话里的敏捷运营报告，四个数据面各占一块](/docs-assets/case-report/zh/S-case-report-04-report.png)

报告覆盖你点名的四个面。示例运行结果，你的实际输出会有所不同。

这份报告同时是一份**产物**——一次运行生成的成品。内置技能把报告直接渲染在对话里；如果这次运行还产出了文件（比如大屏、公文的源文件），到控制台的**运行详情**里找到这次运行，产物区里每个文件都有**下载**，见[产物：大屏、公文、幻灯片与打印](#/docs/artifacts)。

![控制台运行详情的产物区，每个文件带预览和下载](/docs-assets/case-report/zh/S-case-report-05-artifact-download.png)

运行详情里，这次运行产出的文件逐条列出，可直接下载。

## 换个说法也能做到

助手不靠固定咒语。下面两条也是 Demo 现成的快捷提示，触发的是不同技能、不同范围的报告：

- `分析当前迭代的燃尽情况，判断能否按时收尾，说明依据和风险`——它只查迭代这一个面，给出燃尽分析和收尾判断，范围比运营报告窄。
- `用周报模板输出本迭代的进展简报`——它按固定的周报模板出一份简报，版式是定好的。

要点是把你关心的范围说出来：四个面全要，得到运营报告；只要迭代，得到迭代小结。具体措辞不必照抄。

## 网页版与扩展版的差别

两者一致：提出需求、看运行、拿报告、下载产物，做法相同。差别只在数据来源——报告取的永远是你当前所在系统的数据；扩展版里助手可以跨标签页干活，但出报告这件事本身没有形态差别。

## 出问题了怎么办

**报告里的数字和页面上看到的对不上。** 数据是你提问那一刻取的，之后页面上的变动它不知道。重新发一次那句话，让它按最新数据重取一遍。

**某次工具调用显示失败。** 看到一次失败不必紧张，助手通常会换个办法继续。如果整次运行都失败了，展开运行流程复制运行 ID，到控制台的[运行记录](#/docs/console-runs)里查原因。

**你要的其实是投屏用的大屏，不是对话里的报告。** 那是另一个技能。发这条快捷提示：`在新窗口打开当前项目的交付监控大屏：迭代进度、缺陷分布、测试质量与 DORA 指标一屏总览`——它会在新窗口打开一块深蓝大屏；本章的报告技能只把报告画在对话里，两者别搞混。
