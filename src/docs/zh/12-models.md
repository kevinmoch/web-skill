# 选择模型

用哪个模型回答你是可以自己选的：按会话换，当场生效。这一章讲在哪儿换、模型名旁边的能力标记是什么意思，以及没配模型、模型不可用时界面会怎么提示你。

## 你能做什么

- 在输入区按会话切换模型，当场生效，不用新建会话
- 看懂「模型能力」标记：可用工具 / 无工具、可传图片 / 不可传图片
- 知道换模型会影响什么、不影响什么
- 认出演示模型，知道它的回答不能当结论用
- 没配模型或条目置灰时，知道去哪儿处理

## 在哪儿切模型

输入区底部那排入口里有一个 **模型** 按钮，按钮上写的是当前会话在用的模型名。点开是模型菜单：打勾的是当前项，点另一项立即切换。

![模型菜单展开：列出可选模型，当前项打勾，不可用的条目置灰](/docs-assets/models/zh/S-models-01-menu.png)

切换只对当前会话生效，也不用刷新页面。三条边界先知道：

- 换一个会话，用的可能是另一个模型；**新建会话用默认项**。
- 在这里换模型**不会改动全局默认项**；默认项在控制台 [连接](#/docs/console-connections) 组的大模型页设置。
- 菜单里的模型列表也来自大模型页：那里改了名称、增减了条目，菜单当场跟着变。

每条助手消息的右下角会标注产生它的模型名，翻旧会话也看得出当时用的是哪一个。

## 模型能力标记是什么意思

模型菜单旁边有一组 **模型能力** 标记：两个小图标，指针悬停上去（读屏会直接朗读）显示文字：

| 标记 | 含义 |
| --- | --- |
| 可用工具 / 无工具 | 这个模型能不能调用工具 |
| 可传图片 / 不可传图片 | 能不能给它发图片附件 |

工具是助手能执行的一个具体动作，比如「读取需求列表」「跳转到某个页面」；技能是打包好的「做某件事的说明书」，装上之后助手就会干这件事。**「无工具」的后果比字面大得多：模型不支持工具时，助手不能调用技能，也不能读页面、操作页面——只能纯聊天。** 你觉得「助手突然变笨了」，头号原因就是这个：多半是当前模型不支持工具，不是助手坏了。

![M-13 模型能力决定你能做什么：当前模型分出「支持工具？」「支持图片？」两个判断，各自导向能做与不能做的事](/docs-assets/models/zh/M-13.svg)

两个标记里，支持工具决定助手能不能干活，支持图片只决定它能不能看图。

![输入区的模型能力标记：工具与图片两个小图标](/docs-assets/models/zh/S-models-02-capabilities.png)

悬停图标能看到文字；显示「无工具」时还会附带原因：「不可用：当前选中的模型不支持工具调用。」

「不可传图片」的影响很局部：给它发图片附件会被拦下，提示「当前模型不接受图片」，换一个有 **可传图片** 标记的模型即可。图片与附件的更多细节见 [附件、图片、语音与拍照](#/docs/attachments)。

## 没配模型会怎样

一个可用模型都没有时，点发送（或点 **模型** 按钮）不会开始对话，而是弹出引导「**尚未配置大模型**」：大模型尚未配置，请先前往大模型配置页面完成配置，再开始对话。点 **配置大模型**，就会跳到控制台 [连接](#/docs/console-connections) 组的大模型页。

![「尚未配置大模型」的引导与配置入口](/docs-assets/models/zh/S-models-03-no-model.png)

另一种情况是**菜单里的条目置灰、选不上**：悬停上去显示「不可用：该条目既没有 API 密钥也没有基础地址，请在控制台补全。」——到大模型页把它补全，或者删掉。

## 演示模型

一个真实模型都没接上时，助手由内置的 **演示模型** 应答：回复是演示文本，并标注「演示模型」。Demo 站点开箱即用、你还没配模型就能聊起来，靠的就是它。

- **用途**：不用填任何密钥，就能把对话流程完整走一遍。它不连真实模型服务，也不发起网络请求。
- **局限**：演示文本不代表它真的读了你的数据和页面，内容只能用来熟悉界面，不能当结论。要它真干活，就去大模型页配一个真实模型。

看到「演示模型」标注，就知道这条回答只是演示。

## 换模型会影响什么

- **能力与风格。** 能力标记跟着当前模型走；不同模型的回答风格、速度也不同。同一个问题换个模型再问，回答不一样是正常的。
- **只影响接下来的回答。** 已经产生的回答不会变，消息上的模型标注也保留。
- **不动全局默认项。** 会话里换模型是临时的；新会话仍然用默认项。

## 浏览器自带的 AI

添加模型时，供应商里除了 OpenAI 兼容 / Anthropic / Google，还有一档 **Chrome 内置（实验）**。界面对它的说明是：「经浏览器 Prompt API 完全在本机运行，不需要端点与 API Key。」——对话时不向任何服务器发模型请求。

两个限制要知道：

- 它**不支持工具调用**，界面的原话是「内置模型不支持工具调用，需要执行脚本的技能在这一档跑不起来」。选中它，能力标记就是 无工具、不可传图片，助手只剩纯聊天。
- 它只在 Chromium 内核的浏览器里提供，还要先开启对应开关、等浏览器把模型下载完。没就绪时，大模型页会写明具体原因（比如「本机模型尚未就绪，Chrome 需要先完成下载。」），菜单里这个条目置灰——选不上，而不是选了才报错。

## 网页版与扩展版的差别

模型菜单、能力标记、配置入口，两者一致。唯一的差别来自浏览器自带的 AI 这一档：它要求 Chromium 内核，扩展版运行在 Chrome 上，天然满足；网页版则取决于你用什么浏览器打开。

## 出问题了怎么办

- **助手突然不调技能、不读页面，只会聊天。** 看模型能力标记是不是 **无工具**：是，就换一个有 **可用工具** 标记的模型；如果是自己配的模型，再到控制台大模型页检查它的「支持工具调用」开关是不是被关了。
- **想选的条目置灰。** 悬停看原因：缺 API 密钥或基础地址，就去大模型页补全；Chrome 内置档置灰则是浏览器侧没就绪，按大模型页写的具体原因处理。
- **发送时弹出「尚未配置大模型」。** 点 **配置大模型** 去大模型页添加一个模型；怎么填地址和密钥，见 [连接](#/docs/console-connections)。
- **图片发不出去，提示「当前模型不接受图片」。** 换 **可传图片** 的模型；换了还不行，检查设置里的多模态开关，见 [附件、图片、语音与拍照](#/docs/attachments)。
