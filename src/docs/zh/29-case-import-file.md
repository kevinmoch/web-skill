# 把一份文档里的内容录进系统

需求、验收标准已经写在 Word 里了，不想再往系统里敲一遍——把文件交给助手，让它读出来、替你逐条录进去。

先说清这份文件去了哪：docx 是在你自己的浏览器里读成文字的，发给模型的只是读出来的正文文字，原文件不会整份发出去。更多数据去向见[隐私与数据去向](#/docs/privacy)。

![M-29 一份文件变成系统里的记录：选文件、【在你的电脑里】读成文字、文字发给助手、它复述准备录什么、你确认、逐条填表、每条提交前确认、录入完成](/docs-assets/case-import-file/M-29.svg)

「在你的电脑里」那一格标明了：读取在本地完成，原文件没有整份发出去。

## 开始之前

- 打开 [Demo](/demo)，选定一个项目，进入需求池。
- 带附件的需求行内有一个 .docx 链接，点一下即可下载——现成的练习文件。

## 第一步：把文档交给助手

1. 把刚下载的 docx 拖进输入框，或点输入框下方的**添加附件**选择它。
2. 小片上的类型标签是「文档正文」，发出去之前随时可以移除。

![把 docx 拖进输入框，附件小片上的类型标签显示「文档正文」](/docs-assets/case-import-file/zh/S-case-import-01-docx-chip.png)

挂进输入框不等于发出去——你点**发送**才算数。

## 第二步：说清要它录什么，先核对再放手

1. 配上你的要求，比如：`照这份文档，把里面列的需求建到需求池`
2. 助手会先复述它读到了什么、准备录哪几条。**在这儿核对一遍**——文档表格复杂、格式花哨时，读出来的内容可能有出入，现在改比录完再逐条改省事。

![助手复述从文档里读到的内容，列出准备录入的条目](/docs-assets/case-import-file/zh/S-case-import-02-restate.png)

复述这一步就是留给你核对的。示例运行结果，你的实际输出会有所不同。

## 第三步：看它逐条录入

1. 多条内容会变成一份**任务清单**，标题旁的进度数字（如 3/7）告诉你录到了第几条。
2. 它把字段逐个填好——这一步不打断你。但和[说一句话，它替你把表填好](#/docs/case-fill-form)同一条规矩：**它可以自己把整张表填满，但按下「提交」之前一定会停下来问你。**每条都弹授权卡（标题**需要授权**），看清填好的内容再点**允许**。
3. 某条填得不对，直接在页面上改，改完再点允许；这条不想要，点**拒绝**——只是这条不写入，后面的照常继续。

![任务清单显示多条录入的进度，含进行中与已完成的条目](/docs-assets/case-import-file/zh/S-case-import-03-progress.png)

进度数字随录入逐条推进。示例运行结果，你的实际输出会有所不同。

![一条需求已被填进表单，提交前弹出授权卡](/docs-assets/case-import-file/zh/S-case-import-04-form-consent.png)

表单已填好、授权卡挡在提交前——每条写进系统都要你点头。示例运行结果，你的实际输出会有所不同。

![全部录入完成后的需求列表](/docs-assets/case-import-file/zh/S-case-import-05-list-done.png)

录完的条目真的出现在列表里。示例运行结果，你的实际输出会有所不同。

## 换个说法也能做到

- `这个文件里的验收标准，逐条加到当前需求上`
- `先别录，你先说说你从这份文档里读到了什么`——只读不写，推荐给第一次用的人
- 也可以点 Demo 现成的快捷提示：`读取我当前正在看的需求列表里带附件的那几条需求文档，抽出验收标准，并列出文档里有、需求单里缺的条目`——它直接读列表里挂着的文档，只比对、不录入。

## 网页版与扩展版的差别

两者一致：读取、核对、录入、提交前确认，行为相同。

## 出问题了怎么办

- **文档很长，它像没读完。** 读出来的文字超过 32K 字符会被截断。分段传，或先说清只要哪一部分，例如「只录第三章的验收标准」。

![文本超长被截断时的提示](/docs-assets/case-import-file/zh/S-case-import-06-truncated.png)

- **它复述的内容和文档对不上。** 别让它动手，把那一段直接复制给它更稳。
- **其中一条不想录了。** 在那条的授权卡上点**拒绝**，这条不会写进系统，其余条目不受影响。
