# 跨标签页工作

> **仅扩展版**：同时在多个浏览器标签页之间工作、跨网站汇总，是扩展版独有的。「逐项处理一个列表」则网页版也能做：系统自带页签栏时走应用内的页签，没有页签栏时同站内靠「跳转 + 后退」。两种形态各自能到哪一步，见文末差别小节。

扩展版助手住在浏览器的侧栏里，一轮任务里能同时在好几个标签页之间工作：它自己来回翻页、读取，把分散在各页的结果汇总给你。这章讲怎么用，以及边界在哪。

## 你能做什么

- 让助手同时参考多个标签页，把分散在几个网页里的信息汇总成一份结论。
- 把一个列表交给它逐项处理：它自己打开、读完、回来、进下一项，中途不用你动手。
- 随时知道它正在哪一页上干活，也能随时叫它回到你这一页。
- 清楚它碰不到什么：你自己开的其他标签页，还有你的画面。

## 一次处理多个网页

网页版助手住在某一个网站里，够不着浏览器标签页这一层。扩展版一轮任务里能用的页面是一组，叫它的**工作集**：你让它开始干活的这一页（起点页），加上它自己的操作新打开的页面。

两点先知道：

- **它不能凭空开页。** 发它一个网址让它新开一页，它做不到；只有它的操作带出来的页面（比如点开一个在新标签页打开的链接）才进得了工作集。
- **单页的规矩原样适用。** 有副作用的操作照样先弹卡问你，见[让助手操作页面](#/docs/page-actions)。

## 让它逐项处理一整个列表

这是多标签页最实用的用法。给它一个列表——订单、需求、工单——说一句「逐项看一遍，把有问题的挑出来」，它会自己一项一项打开、读完、回到列表、进下一项，最后把所有结果汇总给你，中途不需要你做任何操作。

做法一句话能说清：进一项 → 读完 → 回到列表 → 进下一项，循环到做完。层数也不止一层：从列表进详情、详情里再进下一级，至少三层的下钻和逐层回退都支持。完整过程下一节用一个例子走一遍；网页版能到哪一步，见文末差别小节。

示意图（非真实截图）：逐项处理列表的过程——它自己进详情、回列表、进下一项，循环到做完。

## 一个设想的例子：从需求到缺陷的一张总表

> **提示**：本节是设想场景，用来把全过程讲具体，你所在系统的页面结构可能不同。

设想你在一个 Agile 管理系统里看需求列表，一条需求一行，行末有「查看迭代」链接。你说了句：`把每条需求的迭代和没解决的缺陷都查一遍，汇总成一张表。`接下来：

1. **它点开第一行需求的链接。** 弹出一个新标签页（带页签栏的系统里是应用内的页签），里面是该需求的迭代表格。你会看到标签栏上多了一页——它新开出来的，正在那一页上干活。
2. **它读完迭代表，再逐行点进迭代。** 每点一行又弹出一个新标签页，里面是这个迭代还没解决的缺陷。看完就关掉那一页，再点下一行。
3. **回到需求列表，进第二条需求。** 同样的动作对每条需求重复一遍：开页、读表、下钻、关页、回列表。
4. **最后你拿到一张总表。** 每条需求一行：有几个迭代、共多少条没解决的缺陷，哪条最重一眼可见。

![设想场景的下钻流程：需求表里点某行的链接，新标签页打开该需求的迭代表；再点某条迭代的链接，新标签页打开该迭代的缺陷表；读完回列表，处理下一条](/docs-assets/tabs/zh/S-tabs-07-scenario-drilldown.svg)

示意图（非真实截图）：它开着某条需求的迭代表，逐行点进缺陷页。

需求表 → 迭代表 → 缺陷列表，每一层都开在独立的标签页里。

下面是示例（非真实数据），最终汇总总表大致长这样：

| 需求 | 迭代数 | 未解决缺陷数 |
| --- | --- | --- |
| 需求 A：下单流程改版 | 3 | 2 |
| 需求 B：报表导出 | 5 | 7 |
| 需求 C：消息通知 | 2 | 0 |
| 需求 D：权限管理 | 4 | 5 |

最终交付的总表，每条需求一行。

它最多同时开几页？起点页、当前需求的迭代表、当前迭代的缺陷页——**3 页**。就算 20 条需求、每条 5 个迭代，累计开一百多次，同时开着的始终只有两三页——它通常读完就关。32 页的上限只有在你让它「留着页面慢慢对照」时才可能撞上；真撞上会怎样，见下节。

## 助手能用哪些标签页

这是本章最重要的边界：**助手只能用工作集里的页面。**

- **你自己开的其他标签页，它连看都看不到。** 任务开始后你再开的、早就开着的，都不在它的清单里——地址和标题都不会出现。想让它看你正在看的另一页，切过去再开口，它会跟着你到那一页。
- **起点页它关不掉。** 这一页属于你：它读得、点得，但关不掉。
- **扩展自己的页面它不接管。** 比如你打开扩展的设置页，它不会跟进去。

![M-16 工作集的边界：一侧是工作集内的页面——起点页与它自己打开的页面，标注最多 32 页的上限和「进一项 → 读完 → 回列表 → 进下一项」的循环；另一侧是你自己开的其他标签页，助手看不到](/docs-assets/tabs/M-16.svg)

边界是硬隔离：工作集内的它能用，工作集外的它感知不到。

下面是示例（非真实数据），跨页汇总结果大致长这样：

| 页面/条目 | 读到的要点 |
| --- | --- |
| 需求列表 | 共 4 条需求，行末有「查看迭代」链接 |
| 需求 A 的迭代表 | 3 个迭代，当前迭代未结束 |
| 迭代 3 的缺陷页 | 还有 2 条未解决缺陷 |
| 需求 B 的迭代表 | 5 个迭代，缺陷集中在迭代 2 |

它在页面之间的每次切换和读取都列在运行流程里。

## 它一次最多开多少页

一轮任务里，工作集最多同时容纳 32 个页面。上限由提供系统的人设定，可在 2 到 32 之间调整，但界面上没有给你改的入口——更值得学会的是撞上限时的应对。

**撞上上限时你会看到：** 它在没做完的情况下收尾，拿已经读到的部分给你结论，没读到的部分就没有。它没有办法向你要更多配额，所以不会提示你去调——它自己也要不来。

**怎么办：** 把范围说小一点，分两轮跑。`先看前 20 行`、`只看这一类`，都比「全部看一遍」更有可能一次做完。

另外两种情况，你会发现「那一页」用不了了：

| 现象 | 是什么 |
| --- | --- |
| 刚看过的那一页忽然点不动了 | 那一页被关掉或跳走了，已不在工作集里，让它重新列一次可用的页面再继续 |
| 换了个新对话，它认不出之前的页面 | 页面的引用不跨会话，新对话里从当前这页重新开始 |

![撞上容量上限的收尾流程：它一页一页地开，同时开着的页面数增加，到 32 页上限时把手头这些处理完就收尾，并告诉你哪部分没做完](/docs-assets/tabs/zh/S-tabs-06-capacity-wrapup.svg)

示意图（非真实截图）：到 32 页上限时，它把手头这些处理完就收尾，并告诉你哪部分没做完。

撞上限后它会提前收尾，结论只基于已读到的部分。

## 它会抢我的画面吗

不会。它在页面之间切换，切的是它自己的焦点，你面前的浏览器一动不动；一轮任务结束后，你之前在看哪一页，就还在哪一页。

当它手上的页面和你正在看的不是同一页时，侧栏里会出现提示「助手正在另一个标签页上工作 — 页面名」，带一个按钮「切到我这一页」：点了它就回到你这页；不点，它继续在那一页干活，你的画面照旧。

## 网页版与扩展版的差别

| | 网页版 | 扩展版 |
| --- | --- | --- |
| 多个浏览器标签页之间 | 做不到 | 支持（限工作集内） |
| 跨网站汇总 | 做不到 | 支持 |
| 应用内页签之间逐项处理 | 系统自带页签栏并接入后可以 | 支持 |
| 同站内逐项往返 | 靠「跳转 + 后退」可做 | 支持 |

第三行值得多说一句。有的系统自己带页签栏：点一个链接，系统在应用内新开一个页签，而不是新开浏览器标签页。这类系统接入对应能力后，网页版助手也能在页签之间逐项工作——它打开的页签会出现在页签栏上，你看得见、点得进去、也能随手关掉；边界是同一套：只用被允许的页面，不抢你正在看的页签。你所在的系统有没有这个能耐，问提供系统的人。

扩展版的边界照旧：工作集外的页面它看不到；不动你的画面，一轮之后焦点原样；一轮最多同时开 32 页（可在 2 到 32 之间调），撞上限会中途收尾，且没办法向你要更多配额。整体差别见[网页版与扩展版](#/docs/editions)。

## 出问题了怎么办

- **它说某一页用不了、找不到了。** 那一页被关掉或跳走了，已不在工作集里。让它重新列一下现在能用的页面再继续。
- **新对话里它不认得之前看过的页面。** 页面的引用不跨会话。切到那一页，重新说一句从哪开始。
- **它没做完就给了结论。** 多半撞上了一轮 32 页的上限。把范围说小（前 20 行、只看一类），分两轮跑；它没法向你要更多配额，不会主动提这件事。
- **想让它看你早就开着的另一个标签页。** 它看不到你自己开的页面。切到那一页再开口，它会跟着你过去。
