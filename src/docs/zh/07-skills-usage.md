# 技能：让助手会干专业活

你让助手出周报、做监控大屏时，背后真正干活的是技能。读完这章，你会用一句话调动它们，也会确认它这次用了哪个。

## 你能做什么

- 用一句自然语言，让助手产出报告、大屏、公文、幻灯片或分析结论。
- 不用记任何技能名——说清楚你要什么，助手自己挑技能。
- 在消息和运行流程里看到这次实际用了哪个技能。
- 在控制台的技能库里查看全部已安装技能。

## 技能是什么

技能是一份打包好的「做某件事的说明书 + 脚本」，装上之后助手就会干这件事。你所在的系统装了哪些技能，决定了助手会干哪些专业活。

以 Demo（Agile Studio）为例：它预装了 13 个内置技能，按产物形态可以分成五类。产物就是一次运行生成的成品，比如一份报告、一块大屏页面。

| 类别 | 内置技能 | 产物 |
| --- | --- | --- |
| 报告类 | `sprint-progress-report`、`sprint-weekly-brief`、`agile-ops-dashboard`、`cross-project-health` | 直接显示在对话里的结构化报告 |
| 大屏类 | `agile-ops-screen`、`authored-screen` | 独立窗口打开的监控大屏，适合投屏 |
| 公文类 | `quality-bulletin`、`authored-bulletin` | 可打印的通报公文 |
| 幻灯片类 | `agile-slide-deck`、`authored-slides` | 可放映、可导出 PDF 的演示文稿 |
| 分析类 | `requirement-doc-digest`、`bug-screenshot-triage`、`sprint-closeout` | 针对当前页面或项目的分析结论 |

你说了话之后发生的事，可以用一张图概括：

![从一句话到技能产出：你的需求经过路由、激活、在沙箱里执行，最终产物回到对话；路由这一步有分叉——笼统地要走现成的技能，限定了范围或提了要求走现做的](/docs-assets/skills-usage/zh/M-07.svg)

助手先判断该用哪个技能，激活后在沙箱里运行，最后把产物送回对话——这些阶段名（路由、激活、执行、完成）和你在运行流程里看到的一一对应。判断时有个分叉：笼统地要走「现成的」技能，限定了范围或提了要求走「现做的」技能。

## 怎么触发一个技能

**不需要记技能名，也不需要背固定句式。** 用自然语言把你要的东西说清楚就行。比如下面三种说法，说的都是「看看当前迭代进展如何」，多数情况下会激活同一个技能：

- `分析当前迭代的燃尽情况，判断能否按时收尾，说明依据和风险`
- `分析当前迭代的燃尽偏差，定位是哪些需求拖慢了进度`
- 这个迭代能按时做完吗？

前两条原样来自 Demo 欢迎页「试试这些示例」的快捷提示；第三条是随手打的大白话。助手判断的是你的意图，不是措辞——与其背咒语，不如把「要什么产物、取哪段数据」说具体。

![同一需求的两种说法都触发了同一个技能](/docs-assets/skills-usage/zh/S-skills-04-two-phrasings.png)

两种不同说法激活了同一个技能——不需要背固定句式。示例运行结果，你的实际输出会有所不同。

> **提示**：如果一次没说清，助手可能弹出卡片向你追问细节，照常回答即可。

## 两种技能：现成的和现做的

大屏、公文、幻灯片这三类产物，Demo 里各有一对技能：一个用固定模板（现成的），一个按你的要求现场做（现做的）。

| 你要的东西 | 现成的 | 现做的 |
| --- | --- | --- |
| 大屏 | `agile-ops-screen` | `authored-screen` |
| 公文 | `quality-bulletin` | `authored-bulletin` |
| 幻灯片 | `agile-slide-deck` | `authored-slides` |

它们对你的实际差别：

|  | 现成的 | 现做的 |
| --- | --- | --- |
| 出活速度 | 快、稳 | 慢一些 |
| 取哪些数据 | 固定的全量口径 | 按你说的范围取 |
| 版式 / 分区 / 配色 | 改不动 | 你说了算 |
| 幻灯片页数 | 固定 | 由内容决定 |
| 生成后想改 | 改不了 | 说一句就重做一版 |

你说的话里出现下面任何一条信号，助手就会走「现做的」：

1. 你限定了数据范围：「当前页面的」「只要这一类」「这段时间的」。
2. 你指定了内容或形式：看哪几个指标、怎么分区、什么配色、分几页讲。
3. 你看完之后提出修改——哪怕只是「配色换成浅色」。

只有你笼统地要一份标准产物（没限范围也没提要求）时才会走现成的，因为它更快更稳：

- 「给我一块运营大屏」→ 现成的，最快。
- 「给我一块只看当前页面需求的大屏」→ 现做的（限定了范围）。
- 「大屏做好了，把缺陷那块换成折线图」→ 现做的（重做一版）。

对现成的产物提修改时，助手不是在原件上微调，而是改用现做的重做一版——你会看到它重新取数、重新出了一份。这不是它没听懂，是固定模板确实改不动。

![笼统地要和限定范围要，激活了不同的技能](/docs-assets/skills-usage/zh/S-skills-06-fixed-vs-authored.png)

同一次会话连问两遍：笼统地要激活了现成的技能，限定范围后激活了现做的——两张并排的技能标记名字不同。示例运行结果，你的实际输出会有所不同。

## 把这次对话变成一个技能

你带着助手把一件复杂的事做成了，可以把这个过程存下来，下次一句话就能重跑。存的时候有四件事要知道。

**一、它会先给你看，再问你要不要存。** 助手弹出一张确认卡，原文是：`将本次对话保存为技能「{name}」？{description}`，换行后是：`它将提交审核，不会直接启用。请逐字检查下方预览，确认没有不应被保存的内容。`界面里 `{name}` 是技能名，`{description}` 是一句技能描述。文案里的「下方预览」是界面原话，实际预览排在文案上方——以界面为准，两处说的是同一份预览。

**二、存下来不等于能用。** 存进去的只是一份等审批的技能：它进了审批队列，要有人审过、发布了才生效。提交后你会看到提示：`「{name}」已提交待审。审批并发布后才能使用。`——在那之前它调不动。

**三、你可以直接跳过去看。** 提交后卡片上会给出一个候选 ID：点 **复制候选 ID** 复制，或点 **去审批** 直接跳到控制台的审批队列。审批怎么走，见[治理与复核](#/docs/console-governance)。

**四、存之前请你自己看一眼。** 那句「请逐字检查下方预览，确认没有不应被保存的内容」是写给你的责任提示：对话里可能有你不想长期保存的东西，比如具体的人名、内部数字、一次性的口令。逐字看过、确认没有，再点保存。

![「保存为技能」确认卡，含技能内容预览](/docs-assets/skills-usage/zh/S-skills-07-save-skill-confirm.png)

确认卡完整展示将要保存的技能内容，「请逐字检查下方预览」这句责任提示就写在卡上。

![提交后的「已提交待审」提示，含候选 ID 与「去审批」](/docs-assets/skills-usage/zh/S-skills-08-candidate-submitted.png)

提交后的提示写明「审批并发布后才能使用」，并给出候选 ID 和「去审批」入口。

> **提示**：如果你没看到这个入口，可能是你所在的系统关掉了它。开关在控制台 → **设置** → **智能体运行时** →「技能自动生成」，Demo 里默认开着。

## 怎么知道它用了哪个技能

助手消息上会带一个**「技能」标记**，写着这次用到的技能名。

![助手消息上的技能标记](/docs-assets/skills-usage/zh/S-skills-01-skill-badge.png)

技能标记直接挂在消息上，一眼可见。示例运行结果，你的实际输出会有所不同。

消息末尾的**「本轮运行使用的技能」**区块会列出这轮用到的全部技能。

![消息末尾的「本轮运行使用的技能」区块](/docs-assets/skills-usage/zh/S-skills-02-skills-used.png)

展开**运行流程**卡片，其中「激活」这一步写着技能名和耗时（例如「激活 sprint-progress-report 3.9s」）。

![运行流程里的「激活」一步，带技能名和耗时](/docs-assets/skills-usage/zh/S-skills-03-trace-skill.png)

## 装了哪些技能

点对话头部的 **设置**，进控制台的 **技能库**（管理技能、查看运行记录的地方）：已安装技能的来源与状态都在这页。Demo 预装的就是那 13 个内置技能；安装与版本管理见[技能管理](#/docs/console-skills)。

![控制台技能库中的 13 个内置技能](/docs-assets/skills-usage/zh/S-skills-05-skill-library.png)

技能库一页看全 13 个内置技能。

## 技能跑在哪里

技能脚本在一个隔离的沙箱里运行——它碰不到你的页面内容和私人数据，只能用你允许过的能力；沙箱与安全的详细设置见[设置](#/docs/console-settings)。

## 网页版与扩展版的差别

技能用法两者一致：同样的触发方式、技能标记和技能库。差别在取数范围——网页版里，技能只能在你当前所在的这个系统里取数（系统内靠跳转和返回也能汇总多个页面）；扩展版里，助手还能读你打开的其他标签页，跨网站汇总的技能能取到更全的数据。

## 出问题了怎么办

**助手只是纯聊天，没有动用技能。** 通常是它判断这件事不需要技能——把你要的产物说具体（「做成一份周报」「生成一块大屏」）再问一次。如果当前模型的能力标记显示「无工具」，它便调不了技能，换一个模型再试，见[选择模型](#/docs/models)。

**技能跑到一半失败。** 消息里会给出失败原因，点 **重试** 再跑一次；反复失败时，到控制台的运行记录里看这一次的详情，见[运行记录](#/docs/console-runs)。

**工具调用显示「被策略拒绝」。** 技能请求的某个能力被安全策略挡住了，比如访问网络或读取文件。到控制台 **设置** 里的 **沙箱与安全** 页放行对应能力，或联系提供这个系统的人，见[设置](#/docs/console-settings)。
