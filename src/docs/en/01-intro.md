# Meet the WebSkill Assistant

Friday afternoon, almost time to leave, and someone asks: can this sprint wrap up on time? Used to be you'd dig through the sprint, count the defects, check the tests, and piece together a conclusion yourself. Now you can send that exact sentence to the assistant on the page, and watch it look up the data and give you a judgment.

## What it can do for you

All three examples run as-is in the [Demo](/demo) (Agile Studio, a sample project management system), and all three sentences are ready-made examples on the welcome screen — one click sends them.

**Build a delivery monitoring dashboard.** Send `Open the current project’s delivery monitoring screen in a new window: sprint progress, defect distribution, test quality and DORA metrics on one page`, and it pulls the current project's real data and opens a dashboard in a new window, ready to cast to a big screen.

![A dark delivery monitoring dashboard, with sprint progress, defect distribution, test quality and metrics each in its own area](/docs-assets/intro/en/S-intro-03-screen.png)

One sentence in exchange for a dashboard you can cast to a screen. Sample run output; your actual output will differ.

**Produce an operations report.** Send `Generate an agile operations report for the current project covering sprint health, requirement distribution, defect hotspots and test quality`, and it looks up data in several passes, then renders the report right into the conversation.

![An agile operations report in the conversation, with four data areas side by side](/docs-assets/intro/en/S-intro-01-report-result.png)

Every number in the report comes from a real query it ran against the system. Sample run output; your actual output will differ.

**Summarize the page you're looking at.** Send `Read the page I am currently looking at and summarize the key information and anomalies`, and it reads the page first, then summarizes from what's actually on it — no copy-paste from you.

![A summary the assistant produced from the page's real data, citing items on the page](/docs-assets/intro/en/S-intro-02-page-summary.png)

The items cited in the summary come from the page itself. Sample run output; your actual output will differ.

## How it differs from an ordinary chatbot

1. **It does work, not just talk.** It can call skills — a packaged bundle of "instructions for doing something + scripts" — to actually look up data and make things: reports, dashboards, documents, slide decks. And answers aren't just text: tables and charts render right into the conversation.
2. **It knows what you're looking at.** It can read the page you're currently viewing, and its answers cite the real numbers and items on it — no copy-paste from you.
3. **The process is transparent.** Every step it takes is out in the open: what it's thinking, which data it queried, which actions it took — all visible, all traceable.

Open its welcome screen and you can try it right away: under "How can I help you today?" sits the "Try an example" quick-prompt area — ready-made prompts listed right there, and clicking one is the same as sending that sentence.

## What it won't do

- **It never acts behind your back.** Operations that genuinely change the page — clicking, submitting, uploading — always pop up a card to ask you first; it acts only after you click allow.
- **It won't read password fields.** What's typed into a password field is never read, and never remembered.
- **It doesn't guarantee it's right every time.** Answers are generated by a model and can be wrong. Verify important conclusions yourself — the good news is that every number in a report traces back to a concrete query, so there's something to check against.

## Web version vs. extension version

The assistant comes in two forms: the **web version** embedded in a website, and the **extension version** installed on your browser. This chapter's three examples run in both forms, with the same usage; the difference is only how much the assistant can see and touch. To tell which one you're using, see [Web and Extension Editions](#/docs/editions).

## When something goes wrong

**You can't find the assistant on the page.** In the Demo, the entry is **Expand AI copilot** on the right edge of the page. In other systems, what the entry looks like and where it sits is up to that system — if you can't find it, ask the people who provide the system.

**It only chats, it doesn't work.** Look at the model capability badges in the input area — when they show "No tools", it can't call skills; switch to another model and try again, see [Choosing a Model](#/docs/models).

**The data in its answer doesn't match what you see.** It pulled the data at the moment you asked; it doesn't know the page changed afterwards. Send the same sentence again and it will pull the latest data.
