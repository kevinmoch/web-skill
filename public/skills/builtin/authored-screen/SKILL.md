## 何时使用

当用户要**监控大屏 / 数据看板 / 投屏 / 作战室大屏 / 一屏总览**时使用。
出现下面任何一条，就**必须**用本技能，不要改用固定模板的同类技能：

- 用户限定了数据范围：「当前页面的数据」「只看这一块」；
- 用户指定了看哪些指标、怎么分区、什么配色；
- 用户看完后提出任何修改要求。

只有当用户**笼统地**要一块标准大屏、既没限定范围也没指定指标时，
技能库里若有固定模板的同类技能，那类更快更稳，可以优先用；但它改不动，
用户随后提出任何修改，都要回到本技能重做一版。

## 步骤

1. 先用 `read_skill_file` 读本技能的 `references/authoring.md`。那是文档编写契约：
   允许的标签、五个数据组件的 props、CSS 约束、大屏版式要点。**不要跳过**——
   凭印象写出的占位会被 `publish` 挡下来，白跑一轮。
2. 收集数据。**取哪些数据由你判断，但以用户说的为准**：

   - 用户说了范围（「当前页面的」「只看这一类」「这段时间的」），就按他说的取。
     一屏上多出来的那几块「顺手取的」数据，在用户眼里就是你没听懂他的话；
   - 用户没说范围，就由你决定取哪些：该跨页面、跨工具汇总的就去汇总，
     不要因为保守而少取——大屏缺了关键一块同样算失败；
   - 你判断补一点范围外的数据会让这屏更站得住时可以补，但要么先问用户一句，
     要么在顶栏的数据口径里标明它是额外补充的。

   本技能**不带取数脚本**——取数手段随宿主而异，用你当前会话里能用的一切：
   页面感知工具读当前页面、导航或切标签页到别的页面再读、宿主挂上来的 MCP 工具、
   数据源工具、别的技能刚产出的结果，或者直接问用户。要跨多个页面汇总时**一页一页来**：
   进一页、读完、把要用的数字记下来，再进下一页。
   **每个数字都必须来自你真正读到的内容**：读不到就写「暂缺」或直接告诉用户读不到，
   绝不估算、推测或编造任何数字、名称与日期。同时记下数据出处（页面名 / 工具名 / 数据源 id），
   `publish` 的 `dataSource` 要如实填，它会显示在文档窗口里。
3. 先定版式，再定内容。大屏**不是卡片墙**：照 `references/authoring.md`
   第四节的骨架排——顶栏一条、KPI 一行、下面左中右三栏，中栏是**主视觉**
   （最大的一块，放这屏最该被看到的那张图或那个数）。信息块 6～9 个，其余不上屏；
   块与块要有主次，六块一样大等于没有重点。
4. 写出 `html` 与 `css`，调用 `authored-screen__publish` 投放。
5. 会话里只会出现一个「打开文档」按钮，那是唯一入口：不要再调用 `render_ui`，
   不要重造按钮或链接，也不要提及下载或附件。回复一两句说明这屏放了哪几块，
   提示可以全屏投影，并主动告诉用户**可以直接说哪里要改**。

## 修改

用户提出修改后：以上一次 `publish` 的 `html` / `css` 为底稿，只改他点到的地方，
其余部分逐字保留，然后整份重发再调一次 `publish`。用户没提到的分区被改掉就是缺陷。
若上一版已不在上下文里，直说并重新生成一版。
