## 何时使用

当用户要一份**演示文稿 / 幻灯片 / PPT / 汇报材料 / 路演材料**时使用。
出现下面任何一条，就**必须**用本技能，不要改用固定模板的同类技能：

- 用户限定了数据范围：「当前页面的数据」「只要这一类」「别的不用管」；
- 用户指定了内容或结构：讲哪几页、放哪张图、给谁看；
- 用户看完后提出任何修改要求。

只有当用户**笼统地**要一份标准件（「来一份季度汇报」）、既没限定范围也没提内容要求时，
技能库里若有固定模板的同类技能，那类更快更稳，可以优先用；但它一页都改不了，
用户随后提出任何修改，都要回到本技能重做一版。

## 步骤

1. 先用 `read_skill_file` 读本技能的 `references/authoring.md`。那是幻灯数据契约：
   六种版式各能放多少东西、六种正文块的写法、每一页的**密度下限**。**不要跳过**——
   凭印象拼出的 `deck` 会被 `publish` 逐条挡回来，白跑一轮。
2. 收集数据。**取哪些数据由你判断，但以用户说的为准**：

   - 用户说了范围（「当前页面的」「只要这一类」「这段时间的」），就按他说的取。
     顺手多拉进来的那部分，在用户眼里就是你没听懂他的话；
   - 用户没说范围，就由你决定取哪些：该跨页面、跨工具汇总的就去汇总，
     不要因为保守而少取——汇报缺了关键一页同样算失败；
   - 你判断补一点范围外的数据会让结论更站得住时可以补，但要么先问用户一句，
     要么在页面上标明它是额外补充的。

   本技能**不带取数脚本**——取数手段随宿主而异，用你当前会话里能用的一切：
   页面感知工具读当前页面、导航或切标签页到别的页面再读、宿主挂上来的 MCP 工具、
   数据源工具、别的技能刚产出的结果，或者直接问用户。要跨多个页面汇总时**一页一页来**：
   进一页、读完、把要用的数字记下来，再进下一页。
   **每个数字都必须来自你真正读到的内容**：投在屏幕上的数字是要被追问的，读不到就写「暂缺」
   或直接告诉用户读不到，绝不估算、推测或编造任何数字、名称与日期。
   同时记下数据出处（页面名 / 工具名 / 数据源 id），`publish` 的 `dataSource` 要如实填。

3. 先想清楚叙事线：封面 → 结论 / 总体盘面 → 分维度展开 → 风险与建议 → 收尾。
   然后**每一页配上它该有的数据**：这份技能的目的就是把你取到的数字投上屏，
   一整份只有文字要点的幻灯片会被 `publish` 直接挡回来。
4. 拼出 `deck` 对象，调用 `authored-slides__publish` 投放。
   你交的是**数据**，不是 HTML/CSS：版式、字号、配色由技能统一决定。
   这换来两件事——屏幕上那份和另存的 PPTX 是同一份东西；以及**字号不可能被写小**，
   因为你根本没有写字号的地方。
5. 会话里只会出现一个「打开文档」按钮，那是唯一入口：不要再调用 `render_ui`，
   不要重造按钮或链接，也不要提及下载或附件。回复一两句说明叙事线，
   告诉用户可用方向键翻页、可打印 PDF、可另存 PPTX，并主动告诉用户**可以直接说哪一页要改**。

## 版面不能空

用户抱怨最多的就是「一页只有三行字，版面很空」。技能已经把这条做成了硬约束：

- 每种版式的槽位数是**定死**的：`single` 一格、`split` 两格、`grid` 三到四格。
  内容不够就换更少格的版式，而不是让一格里放一行字；
- 正文槽位有**内容下限**：一组要点至少 3 条，一段话至少要是完整一句，
  指标卡至少 2 张，键值清单至少 3 行；
- `single` / `split` / `grid` / `closing` 每一页都**必须**写 `takeaway`——
  一句结论，同时填满版式给它留的底栏；
- 整份至少要有一页带图表、表格、指标卡或键值清单。

挡回来时不要靠「把文字拆成更多条」凑数，回去把该页的数据补上。

## 修改

用户提出修改后：以上一次 `publish` 的 `deck` 对象为底稿，只改他点到的那几页，
其余页逐字保留，然后整份重发再调一次 `publish`。不要图省事重写全部——
用户没提到的页被改掉就是缺陷。若上一版已不在上下文里，直说并重新生成一版。
