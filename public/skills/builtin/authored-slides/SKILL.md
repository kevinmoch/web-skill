## 何时使用

当用户要**幻灯片 / 演示文稿 / PPT / 汇报材料 / Slide**时使用。
出现下面任何一条，就**必须**用本技能，不要改用固定模板的同类技能：

- 用户限定了数据范围：「当前页面的数据」「只讲这一块」；
- 用户指定了讲什么、分几页、每页放什么；
- 用户看完后提出任何修改要求。

只有当用户**笼统地**要一份标准汇报片、既没限定范围也没提内容要求时，
技能库里若有固定模板的同类技能，那类更快更稳，可以优先用；但它一页都加不了，
用户随后提出任何修改，都要回到本技能重做一版。

## 步骤

1. 先用 `read_skill_file` 读本技能的 `references/authoring.md`。那是文档编写契约：
   reveal.js 的结构与 CSS 陷阱、五个数据组件的 props、每页的信息密度要求。
   **不要跳过**——幻灯片这条路上的坑（打印时选择器失配、section 撑不满）
   凭印象一定会踩。
2. 收集数据。**取哪些数据由你判断，但以用户说的为准**：

   - 用户说了范围（「当前页面的」「只讲这一类」「这段时间的」），就按他说的取。
     顺手多拉进来的那几页，在用户眼里就是你没听懂他的话；
   - 用户没说范围，就由你决定取哪些：该跨页面、跨工具汇总的就去汇总，
     不要因为保守而少取——汇报缺了关键一环同样算失败；
   - 你判断补一点范围外的数据会让这份汇报更站得住时可以补，但要么先问用户一句，
     要么在那一页上标明它是额外补充的。

   本技能**不带取数脚本**——取数手段随宿主而异，用你当前会话里能用的一切：
   页面感知工具读当前页面、导航或切标签页到别的页面再读、宿主挂上来的 MCP 工具、
   数据源工具、别的技能刚产出的结果，或者直接问用户。要跨多个页面汇总时**一页一页来**：
   进一页、读完、把要用的数字记下来，再进下一页。
   **每个数字都必须来自你真正读到的内容**：读不到就写「暂缺」或直接告诉用户读不到，
   绝不估算、推测或编造任何数字、名称与日期。同时记下数据出处（页面名 / 工具名 / 数据源 id），
   `publish` 的 `dataSource` 要如实填，它会显示在文档窗口里。
3. 先列大纲，**页数由内容决定**：把你取到的数据里真正站得住的论点列出来，一个论点一页，
   前面加封面、后面加结论页。论点只有两个就出四页，有十个就出十二页。
   **不要预设一个固定页数**，也不要为凑页数把一个论点拆成两页、或加一页没数据的「展望」。
   用户给了页数或大纲就严格照办。
4. 写出 `html` 与 `css`，调用 `authored-slides__publish` 投放。
5. 会话里只会出现一个「打开文档」按钮，那是唯一入口：不要再调用 `render_ui`，
   不要重造按钮或链接，也不要提及下载或附件。回复一两句说明这份幻灯片的脉络，
   提示「方向键翻页、右上角打印按钮导出 PDF」，并主动告诉用户
   **可以直接说哪一页要改**。不要复述幻灯片上的数字。

## 修改

用户提出修改后：以上一次 `publish` 的 `html` / `css` 为底稿，只改他点到的那几页，
其余页面逐字保留，然后整份重发再调一次 `publish`。用户没提到的页被改掉就是缺陷。
若上一版已不在上下文里，直说并重新生成一版。
